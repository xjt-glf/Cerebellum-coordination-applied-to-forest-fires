# 面向冻结执行器的经验教练：实现方案与验证计划

日期：2026-10-22。状态：研究设计与相关工作调研，尚未实现或证明有效。本文不修改Actor、现有实验或前端。

2026-10-24补充：进一步查到COUNTERMEM与EvoCF，反事实验证、条件经验记忆及多智能体计划评价也有直接先例。最新查新与收窄后的候选方向见 [执行后LLM评价与长期经验调研](llm_critic_memory_novelty_20261024.md)；不要把本文的通用组件组合当成已确认原创。

## 1. 判断

值得做。现有结果提示，执行器经验、历史反馈的组织和决策流程可能影响大脑效果。但“千问输是因为上下文短”尚未得到验证：现有调用每轮包含完整真值环境、部分执行器提示，以及full_snapshot写入的最近5次决策。它缺少的可能是跨回合积累、经验证的经验，以及按当前问题提取经验的机制，而不是完全没有历史或输入不够长。

Codex与千问的对比同时改变了模型、上下文、工具摘要和项目经验，不能孤立归因为某一项。第一步应使用同一规划模型分离这些因素。

教练也有上下文上限。可扩展实现应把知识持久化到外部存储，模型按需读取；第一版通过更新经验库改善行为，不更新任何大模型或Actor权重。这属于记忆/上下文适应；如果后续真正微调，需另列参数训练实验。

## 2. 直接相关的研究

以下来自作者论文或项目资料，非穷尽综述。检索时间2026-10-22。

| 工作 | 已有思想 | 对本项目的启示 |
|---|---|---|
| [Reflexion，2023](https://arxiv.org/abs/2303.11366) | 将执行反馈转为文字反思，存入情景记忆，不必更新模型权重 | “做完复盘，下次读经验”已有先例 |
| [ExpeL，2023](https://arxiv.org/abs/2308.10144) | 从任务经历提炼见解，推理时检索经历与知识 | 单纯检索历史成功案例不是新贡献 |
| [CLIN，2023](https://arxiv.org/abs/2310.10134) | 持续维护关于动作与结果的因果抽象记忆 | 条件化经验与跨任务更新本身也已有研究 |
| [ACE，2025/2026](https://arxiv.org/abs/2510.04618) | 生成、反思和整理分工，逐条增量维护策略知识，避免反复重写丢失细节 | 不能把结构化记忆、增量更新本身声称为原创 |
| [AgeMem，2026](https://arxiv.org/abs/2601.01885) | 将长短期记忆操作纳入策略并训练 | “学习什么时候读写记忆”也有强相关工作 |
| [FRAMe，2026年7月](https://arxiv.org/abs/2607.06964) | 飞行规划LLM结合RAG记忆与多模态教练 | 与“飞行规划＋教练＋记忆”高度接近，必须作为直接对照 |

FRAMe面向eVTOL航线生成，教练结合几何检查、渲染图的偏好评价及可选操作员反馈，并保存结果供检索。本文拟研究的是动态多机任务中，给定冻结RL执行器后，建议能否实际执行、信息能否送到人员、以及经验如何经闭环实验获得有效范围。这个区别是候选研究切入点，尚不足以据此断言方法新颖。

## 3. 建议的核心研究问题

**在规划模型和执行器均冻结时，能否通过理解执行器能力、按需提供具体建议、并用实际闭环结果校验经验，让高层决策持续改善，同时控制上下文和咨询开销？**

重点不是“教练知道更多”，而是三件事的证据：

1. 检索的知识在当前Actor版本、状态和资源条件下适用。
2. 建议包含可执行改动、前提、有效时间和可观察的验收标准。
3. 经验更新能排除错误反思和负迁移，而不只是不断累积自信的文字。

与已有工作区分，需要证明上述机制的额外价值。不能将组件组合或无人机场景迁移本身当成已成立的主创新。

## 4. 系统架构

```text
环境当前状态 + 近期执行反馈
           ↓
       冻结规划LLM ←── 经验检索（小预算、每次可用）
           │
           ├── 需要咨询时：状态 + 草案 + 问题 → 教练
           │                                  ↓
           │                          检索证据 → 结构化建议
           └──────────── 修订计划 ←─────────────┘
                            ↓
             公共目标管理 / 充电保护 / 可选航迹转化器
                            ↓
                       冻结Actor
                            ↓
                       环境实际执行
                            ↓
         事件与结果记录 → 离线复盘 → 实验校验 → 经验库增量更新
```

教练是一个服务角色，不要求单独训练更强模型。同一基础LLM配不同提示和记忆访问权限即可做第一版。使用更强模型作为教练应另做对照，防止将提升误归因于记忆机制。

简单充电可达性、合法坐标、航迹预算等继续由程序检查。教练主要处理任务取舍、历史经验适用性和执行失败归因，避免每20步都为确定性检查额外调用一次大模型。

## 5. 外部记忆分层

| 层 | 内容 | 保存与使用 |
|---|---|---|
| 执行器档案 | Actor哈希、指令契约、到访/跟随成功率、已知失败模式、真实站点 | 常驻精简核心；绑定Actor和协议版本；代码事实与经验假设分开 |
| 回合工作状态 | 各机目标、已完成/未完成、当前人员分组、交班承诺、未解决异常 | 由真实状态与事件维护；随t更新，旧位置不能变成永久事实 |
| 原始经历 | 下指令前状态、请求与实际指令、动作/轨迹、短期机制结果、整局任务结果 | 追加保存JSONL/压缩快照，便于回溯；不全塞入提示 |
| 条件经验 | 在何种资源/位置/能力条件下采取何种调整，何时有用/有害 | 结构化条目，检索后附证据；可修正、退役、拆分适用范围 |

第一版用SQLite元数据和全文检索即可，可增加向量索引。先按Actor哈希、环境/协议版本、资源regime和事件类型硬筛，再做数值状态与语义相似度排序。当前状态含电量、距离和人数，不能只凭文字向量相似就套用经验。

一条经验建议保存：

```text
memory_id
actor_sha / environment_version / protocol_version
trigger / applicability / exclusions
observation                 已测事实
hypothesis                  对原因的解释，允许尚未证实
recommended_edit            任务或目标的相对修改原则
expected_mechanism          下一窗口可观察到的改变
task_tradeoff               可能牺牲的探索、时效或补给能力
evidence_episode_ids / snapshot_ids
validation_status           observed / mechanism_verified / task_verified / rejected
support_cases / adverse_cases / state_range
created_at / last_checked / supersedes
```

不把某次轨迹成功自动写成通用规律。例如“增加中继有用”必须附人员分流、覆盖缺口、剩余感知与补给资源的条件；旧实验已经出现建议价值随资源条件反转的迹象。

旧actor_best.pt上的Critic/建议数据不能直接当新Actor有效建议的标签。可将其作为假设来源，重新在当前actor_selected.pt上验证。

## 6. 在线咨询如何发生

第一版采用可审计的触发条件：

- 规划器主动提出具体问题；
- 未完成目标在合理航程下持续不进展；
- 关键人员持续失联、AoI上升，现有分工解释不了；
- 计划与执行器档案冲突，例如依赖完整patrol绕圈；
- 同类教练经验互相矛盾，或找不到适用证据；
- 轮充与任务交班出现资源冲突。

不能只依赖LLM自报“我很有信心”，它可能自信地重复错误。后续可训练咨询收益预测器，判断预期改善是否值得token和延迟；这是扩展研究，第一版不必先训练复杂门控。

初始工程预算可设为：每次检索3–5条短经验，单次教练最多3条具体修改、一次修订；这是可调起点，不是已验证最优参数。事实档案稳定置顶，详细日志按需读取。

教练输入包括当前状态的时间戳、规划草案、上一段实际结果、明确问题和检索证据。教练输出包括：

```text
issue                       哪架/哪组、什么异常
evidence_ids                支持判断的经验与当前字段
preconditions               执行前必须满足的条件
edits                       可选的结构化目标/角色补丁
expected_observable_change  20步内可核查的机制变化
tradeoffs                   为什么此时值得占用该机
expires_at                  建议仅适用于当前状态/窗口
status                      有证据支持 / 证据不足 / 建议先观察
```

例如：发现人员分为两组、当前中继只覆盖第一组时，教练可建议“由具备返航余量且能及时到达的另一架接管第二组；到位后检查第二组本机链路和AoI；需要暂缓哪块探索”。具体选哪架、哪个人员ID与目标点必须按当前状态计算。不能凭经验生成一组过期坐标，更不能虚构“未来20步肯定多灭10格”。

教练建议经程序检查合法性与能量/航程前提，再由规划器接受或拒绝并记录原因。异步扩展时必须检查Actor版本、t和状态漂移；过期建议不能直接覆盖当前任务。第一版保持同步，以免与现有对照混入时延变量。

## 7. 经验如何更新，避免越学越错

### 7.1 收集

每个20步窗口记录：指令前状态、原计划、咨询问题、检索条目、建议、接受情况、实际下发/充电抢占、执行轨迹、观测与链路变化。每局结束补记累计过火、未合围暴露、探索、AoI、能量等整局结果。无需保存模型私有思考过程，简明理由与可核查决策记录足够。

### 7.2 复盘

教练提出候选解释和经验更新，标记未证实部分。必须区分：规划目标错误、指令被公共协议改写、Actor执行不足、位置冲突、充电抢占、真实环境变化。不要把所有失败都归咎于大脑，也不要把所有成功都归功于建议。

### 7.3 验证

训练/开发阶段可利用已有确定性快照分叉基础设施：从同一状态比较原计划与建议计划，固定同一Actor与公共协议。

- 20步检验到点进度、人员链路、信息变化、能量等机制承诺。
- 任务收益使用整局或充分长期的相同后续策略协议验收；后续高层策略如何处理两个分支必须预先固定，不能一边继续自适应、另一边复用过时计划却称为纯干预贡献。
- 旧研究已提示短窗扑灭差可能是瞬态量。该现象来自旧Actor，不能机械套数值到新Actor，但提醒我们必须重新检查短窗指标与整局目标是否一致。
- 跨多个独立种子、状态和资源regime复验，保留负例、置信区间或适用范围；LLM主观自评不是校准置信度。

在线部署不默认运行未来仿真Oracle。若某组允许在线搜索，应单列计算预算和相应基线。

### 7.4 写入

仅做条目级add/update/retire，保留来源与版本；不要每局把整个经验库重新压缩改写。候选经验先进入待验证区，机制验证通过不自动升级为任务收益已验证。Actor或环境版本改变后，相关经验需要重新检查。

正式冻结测试集上不得把跨测试场景结果写回教练再当独立测试成绩。持续适应应另设协议：固定场景到达顺序、相同初始记忆、统一允许写入的反馈，并报告随经历累积的学习曲线。

## 9. 最重要的实验设计

先用相同规划模型、相同当前状态输入、Actor、公共协议与新种子，验证“经验缺口”假设。以下为建议组别，可先做小规模开发筛选，再冻结设置运行正式测试：

| 组 | 增加的能力 | 要回答的问题 |
|---|---|---|
| A 当前规划器 | 已有提示、当前状态和短历史 | 原基线 |
| B A＋执行器档案 | 加入验证过的能力/接口事实 | 光教会它底层特点是否已足够？ |
| C B＋更长原始历史 | 增加历史上下文 | 是否只是多给历史就能解决？ |
| D B＋普通经验检索 | 检索经历/经验，无在线教练 | 普通RAG是否足够？ |
| E D＋教练建议 | 同一记忆库，冻结不写入 | 在线分析和可执行建议是否有独立价值？ |
| F E＋经验证的增量更新 | 在训练/适应协议内更新 | 持续积累是否改善迁移与抗遗忘？ |

还应对照CLIN/ACE风格的普通反思记忆更新，以及去掉实验验证、去掉Actor版本/能力条件、始终咨询与按需咨询等消融。优先验证核心假设，不必一开始把所有组都铺满。

固定同模型的规划器与教练是干净起点。若用强模型当教练，还需与“强模型直接当规划器”在总调用/token/推理预算相近条件下比较，判断是否只是多花计算换成绩。上下文更长组和检索组分别报告等预算结果和性能—成本曲线，不能隐藏额外输入。

已有三个场景仅用于开发；正式测试采用预留新地图/风/初始位置等种子。候选20–30个配对场景可作启动规模，再根据开发集方差决定正式样本量，不承诺此数量必然获得统计结论。涉及API随机性时评估相同场景多次规划波动，不只重复确定性重放。

指标：累计过火和未合围暴露为任务主指标；有效人员火情认知、探索、覆盖与AoI为过程指标；另报教练建议采纳/失效/有害比例、咨询率、输入输出token、总成本、建议时效，以及记忆规模增长后的表现。统计以场景/回合为独立单位。

成功判据应包括：相同规划模型在新场景上稳定改善；优于仅加档案/普通检索/普通反思；累积经验能迁移而非记住坐标；收益足以覆盖咨询开销。若B已追平E/F，则优先承认执行器说明书解释了差距，无需强推复杂教练。

## 10. 实施顺序

1. 从现有交接文档生成带来源的执行器档案，跑B组先测最便宜解释。
2. 将实际执行记录按事件索引，做只读检索D组；先不引入自动经验写入。
3. 引入结构化、按需咨询E组，检查建议能否执行和产生机制收益。
4. 利用开发集分叉验证经验，再做F组持续适应；冻结新测试集检验泛化。
5. 只有证据支持时再训练咨询门控、经验价值预测器或教练微调模型；Actor继续冻结。

候选论文定位是“针对特定执行器能力、以闭环证据维护的长期决策教练”。目前它是一条可检验的研究路线，尚没有实验增益或新颖性证明。
