# H200 整夜训练计划：目标条件续训优先，必要时从头重训

版本：v1，2026-10-13。用途：随当前项目上传 H200 服务器，供服务器 agent 实现并执行。  
资源授权：最多 8 张 H200，可并行训练与验收；此前“仅 CPU”限制不再适用于本任务。  
默认总时限：从服务器 agent 开始实施起 8 小时，可由用户改为 10 小时或指定截止时间。时间记录使用 Asia/Shanghai；最后 60 分钟留给最终验收和交付。

## 1. 执行目标与范围

交付一套可加载的底层 Actor，让 explore/patrol 真正执行指定目标，同时保持 charge/relay 与整局任务能力。优先继承现有 Actor 定向续训；达到第 9 节的失败条件后，自动转入从头重训。收到此计划作为用户任务后，服务器 agent 可完成实现、冒烟、训练、切换和验收，无需逐阶段等待新确认。

本轮不继续研究高层 Critic，不调用付费 LLM，不部署替换网页当前权重。原权重、原实验数据与源码快照必须保留。训练成功以配套《底层训练验收协议》为准，不以进程结束或 reward 上升为准。

**本项目目前没有本计划所需的新训练入口。** 第 11 节的 CLI 是待实现合同，不是现成命令。不能直接运行原 train_lowlevel.py 的 --resume 并声称已实施本计划。

## 3. 正式训练前必须完成的短修正

### 3.1 修正验收口径，不能直接使用旧诊断平均值作门槛

- diag_skills.py 的 analyze_relay 统计 r.is_covered，包含其他无人机和基站贡献。改为同时报告“受测机到指定人员的实际链路”“人员全队覆盖”“指定任务信息传递”。受测机自身链路才是服从指标。
- explore 的 near/far 当前从四个固定象限中心取目标，没有检查该区域仍未知。新验收和训练只抽取有效目标；已完成区域不能成为服从失败样本。
- explore 的 d_init 当前从第一步后的位置计算；charge 的初始电量也在第一步后取值。改为执行前记录，完整保存首步。
- patrol 的 auto 半径会随已知火簇变化，旧诊断拿初始半径固定计算。明确区分固定半径测试和动态 auto 测试，逐步记录实际解析半径。
- 60×1.41 是运动距离上限，不是所有状态下的可达保证。远目标按实际格点最短步数、地图边界、能量与冲突验证；同条件参考控制器仅用于可达性参考。

重新对旧 Actor 跑一份小规模、正确口径的开发集基线，后续所有候选使用同一固定测试集。

### 3.2 修正一个已复现的混合字段契约不一致

目前 relay 同时给 target=(10,0) 与 rescuer_id=1、人员位置=(0,80) 时：

- resolve_order_target 返回 (0,80)，符合 rescuer_id 优先规则；
- UavOrder.to_vector 仍优先取原 target，编码方向为 (1,0)。

观测中的目标必须与实际解析目标一致。保持显式目标标志的含义，优先编码调用方提供的有效 resolved_target；没有解析值时再使用原 target。补一项受控测试，覆盖 relay 混合字段、单字段、默认目标与 charge。这不需要改观测维度，但必须记录 contract_version。

新旧 Actor 都在同一修正契约下比较；旧网页协议另报一次兼容性结果，避免归因混淆。不要把这项边界问题宣称为全部不服从的根因。

### 3.3 保持物理设定，扩展训练层

不改变火蔓延、通信半径、动作空间、统一能耗和碰撞规则来制造收益。优先新增训练包装器、目标管理器和 RewardV2，保留 RewardV1。正式基础文件只做明确契约修正及兼容扩展，全部变更保存 diff/哈希。

## 4. 目标生命周期与训练分布

### 4.1 explore 目标定义

target 为区域中心，默认区域是裁剪到地图内的 11×11 方形（half_width=5），到访半径为 5 格。生成时区域未知比例至少 0.6，能量允许去往并返航。

任务成功分为：

1. 受测机到访目标区域；
2. 相对指令下发时，该区域未知格中至少 80% 被有效观测。

训练奖励按本机真实新增观测归因，不能奖励队友完成的区域。团队已完成区域可终止/更新任务，但不自动给本机到达奖励。

目标管理器保存 goal_key、初始未知掩码、到访/完成事件和有效期。相同计划重发不得重置一次性奖励；目标失效、完成或明确新指令才换 goal。到达后继续观察目标区域，不因“已到达”奖励在边缘来回刷分。

### 4.2 patrol 目标定义

只给实际认知地图中已发现、未合围的火点。目标含火点与可行环半径；先学习进入环带，再学习持续巡逻与信息刷新。无已知火点时用实际探索暖启动，不将未观测的真值火点直接塞进部署指令。

auto 环半径使用当前解析值；显式半径按指令固定。采样显式半径时排除无法形成合理安全环带的组合，不能用火场内部的小环要求模型违规。

只停在环带某一点不等于巡逻。记录环距、12 个角度扇区覆盖与真实目标火情刷新；地图边界导致全环不可行时单列可行弧段测试。

### 4.3 角色与指令采样

保留 agent ID，但每次新分配在能量可行的机队中随机化角色。统计每个编号的任务曝光和完成率，排查角色固化。

技能阶段以 explore/patrol 为主，同时保留 relay/charge；推荐焦点任务 episode 比例为 35%/35%/15%/15%。这是焦点任务比例，队友仍执行合理支持任务，不是独立随机给每架机分配任务。

主训练场景：100×100、3 个火点、600 步、spread_gain=1、统一能耗、随机风向；人员数 10/14 各半，规划检查周期 20。晚期加入 4 火点压力场景。保留旧配置作为回归测试，不把推断的历史默认值当成唯一训练分布。

当前 VecEnv 同一批次 N 固定，不能直接混合 3 机/4 机的变长数组。初筛固定 N=4；正式阶段在完整 rollout 边界交替 N=4 与 N=3 的训练块，约 75%/25% 环境步。切换时重建 VecEnv/Buffer，继承当前模型和优化器，不复用错误形状的 rollout。若实现代价过高，则单列 3 机适配分支，并明确交付模型的适用范围。

### 4.4 课程阶段与 20 步检查

| 阶段 | 焦点任务比例 E/P/R/C | 目标距离 | 联合任务 |
|---|---|---|---|
| S1 技能建立 | 35/35/15/15 | 主要 8–25 格，部分 25–50 格 | 合法目标，稳定保持指令；覆盖与能量约束保留 |
| S2 距离与角色泛化 | 30/30/20/20 | 8–90 格混合 | 任意编号承担任意角色、移动人员、补给竞争 |
| S3 协同与部署 | 以完整任务为主，约 30% 技能维护 episode | 按真实态势采样 | 3/4 机、10/14 人、3/4 火点、部署式目标更新 |

每 20 步是检查与必要重规划，不是强制替换全部未完成远目标。给定合法目标应保持到完成、失效、紧急能量事件或合理超时。建议超时为 min(160, max(40, 2×最短导航步数+20))，不是固定 20 步。

切换课程优先依据开发集技能进展，也受第 9 节时间门控制；仅在近目标训练到高回报，不能跳过远目标验收。

## 5. RewardV2 与三类候选

所有系数是可审查的初始配置，不是已证明最优值。先用受控导航/巡逻轨迹和旧 Actor 检查奖励排序、事件去重与刷分风险，再开训。

### 5.1 共用原则

- 继续保留时间、越界、碰撞阻挡、能量、耗尽和适度团队损失项。
- 显式 explore 不再主要奖励全图任意位置的新格；只把指定区域中新格/火情作为主体，区域外小权重或无奖励。
- patrol 去掉“自由探索新格”这个可替代目标的主要收入，奖励指定火点附近的有效刷新和合法巡逻。
- 新增目标效率项是明确改变任务目标的基础奖励，不错误宣称全部符合势函数不变性。
- arrival/complete 事件按 goal_key 去重；巡逻扇区奖励只给新的有效覆盖，不能反复左右摇摆刷分。
- reward.parts 必须记录区域内/外、进度、事件、环带、扇区、刷新、安全和旧技能项的真实贡献。
- 本机观测归因以环境实际感知范围及观测前后记录为准，不能把队内融合后的新增地图全部算给本机，也不能假定奖励文件中的近似 foot 半径等于真实传感器范围。
- 同一火点的质心轻微移动、auto 半径更新不创建新的可领奖目标；火点关联和目标事件需要稳定 key，防止每次20步检查重新赚到访奖励。

### 5.2 初始方案 P1 / P2

| 项目 | P1：平衡目标奖励 | P2：强目标奖励 |
|---|---|---|
| explore 区域内新格/新火格 | 保留 0.04/0.40，按本机新增观测归因 | 同 P1 |
| 区域外探索乘数 | 0.05 | 0 |
| 目标距离进度 | 0.05×clip(d_before−d_after, −sqrt(2), sqrt(2)) | 系数 0.10 |
| 首次到访 / 区域完成 | +2 / +3，各 goal 只给一次 | +3 / +5 |
| patrol 环误差进度 | 0.05×clip(err_before−err_after, −sqrt(2), sqrt(2)) | 系数 0.10 |
| 合法环带保持 | +0.02/步，环误差≤3 | +0.04/步 |
| 新有效扇区 | +0.15/扇区/目标刷新周期 | +0.25 |
| 指定火情纠偏 | 复用刷新奖励，限制在目标火点邻域 | 同 P1 |

合法环带内才计角度覆盖。不要因为不同位置单步角度噪声增加扇区数；跨中心的大跳角不计巡逻进度。重复环带保持的收益必须与真正扫描收益对照，防止学成悬停。

没有显式目标的自由探索保留原能力，作为独立任务子类和回归测试。输入维度先不扩展；所有“成功/完成”状态由包装器管理并通过 info 给高层，不偷偷覆盖 Actor 动作。

relay/charge 初始沿用原奖励。先用正确的本机覆盖指标验收旧 Actor；若 relay 自身目标跟随低于门槛，再加入指定人员链路奖励，而不是沿用被全队覆盖掩盖的高分。

### 5.3 P3：P1＋示范热身

从合法导航、可行巡逻和经过验收的旧技能获取观测—动作示范。示范只能使用控制时可知状态，动作遵守同一碰撞与能量规则。先监督热身，再用 P1 做 PPO。

推荐初始数据量 5–10 万个单机 transition（记录该单位，勿与 environment-step 混淆）。初始 BC 训练 3–10 个 epoch，按独立开发集停止；不得反复训练到只记住固定目标。对 charge/relay 可用旧 Actor 输出作为保留参考，但只使用正确口径下合格样本。

P3 的正式验收全部由新 Actor 输出动作，不能运行教师或 waypoint_assist 兜底来计成绩。

## 6. 初始化与优化

续训：只加载旧 Actor，保留 hidden=384、2 层、355 维观测、9 动作。新建训练值网络、Adam 与 ValueNorm；新奖励前 5–10 个 update 可只校准值网络，随后训练 Actor。不得直接恢复旧完整 checkpoint 的值归一化与 optimizer 并称为奖励适配。

同一新方案的故障恢复/阶段继续：恢复其完整 checkpoint、optimizer、ValueNorm、累计步数、课程状态与随机数状态。区分 init_actor 与 resume_exact 两条路径，恢复时检查 reward/contract/sampler 版本一致。

| 参数 | 初始值 |
|---|---|
| Actor LR | P1/P3 1e-4；P2 2e-4 |
| 值网络 LR | 3e-4 |
| gamma / GAE lambda | 0.99 / 0.95 |
| PPO clip / epochs | 0.15 / 4 |
| entropy | 0.02 起步，按阶段降到 0.01，不能只靠随机采样掩盖 argmax 不服从 |
| rollout | 128，吞吐测试后可用 256 |
| minibatch | 目标 2048–4096 个单机样本，按实际 batch 自动计算 |
| 数值精度 | FP32 起步；概率、log-prob、GAE、归一化和损失保持 FP32 |
|梯度裁剪 | 起步 1–5，日志记录实际梯度/KL/clipfrac |

PPO 用随机动作探索；开发/最终交付以 deterministic argmax 为主，随机采样仅作辅助结果。若高 KL 或持续回归，降 LR/增加旧技能维护，不靠挑选单个幸运 checkpoint 宣称通过。

## 7. 8 卡并行表与 CPU 预算

默认一张 GPU 一个 trial，CUDA_VISIBLE_DEVICES 映射后进程内用 cuda:0。这个网络较小，8 卡主要用于独立方案和种子，不默认启动单模型 8 卡 DDP。

| GPU | 初筛任务 | seed | 用途 |
|---|---|---|---|
| 0 | P1＋随机角色，Actor 续训 | 1101 | 主方案 |
| 1 | 同 GPU0 | 1102 | 独立训练种子 |
| 2 | P2＋随机角色，Actor 续训 | 1201 | 更强目标约束 |
| 3 | 同 GPU2 | 1202 | 独立训练种子 |
| 4 | P3：示范热身＋P1，随机角色 | 1301 | 快速纠正目标导航 |
| 5 | 同 GPU4 | 1302 | 独立训练种子 |
| 6 | 原奖励＋随机角色，Actor 续训 | 1401 | 角色采样修正对照 |
| 7 | P1＋旧式固定角色，Actor 续训 | 1501 | 奖励修正对照 |

初筛后释放 GPU6/7 及失败 trial，给优胜续训的第三个种子、3 机适配、或重训。固定角色对照不能成为面向任意指派的交付模型。

若只有一个优胜方案，先保留其两个已训练种子继续放大，空闲卡分给第三/第四种子、3机专项适配及示范数据热身对照；若有两个方案则各保留至少两种子。最多8个GPU训练进程，CPU验收共用预算。不要让控制组在已经完成消融后占满剩余整夜资源。

服务器先查实际 CPU affinity/cgroup 限额。训练 worker 总数初始控制在有效 CPU 的约 70%，验收约 15%，其余留给主进程和系统。OMP/MKL/OpenBLAS 与 worker 的 torch 线程各设 1，防止 8 个任务过量开线程。

CPU 充足时每 trial 从 8–16 workers 起步，envs_per_worker=2，n_envs=workers×2；比较 k=1/2/4 的全局吞吐后调整。n_envs 和 n_workers 不同，不能把每卡 64 env 写成每卡 64 worker。

必须同时 profile 八个任务的总吞吐，单任务快不代表八任务更快。若 CPU 重尾等待主导，优先改分组/预算，必要时错峰采样；不要通过扩大网络来人为提高 GPU 利用率。选择设备充分利用、有效采样最多且训练稳定的配置。

环境 worker 不持有 CUDA 上下文；在初始化 CUDA 前启动 fork worker，或使用可 pickle 的 factory＋spawn/forkserver。不能在已初始化 CUDA 的进程里随意 fork。评估可在有限 CPU worker 中加载 Actor 快照异步进行，不能让八个 trial 各开一套无限评估池。

| T+3.5 小时 | 续训是否转重训的主决策点；给重训留出至少约 3 小时 |
| T+3.5～7 小时 | 续训放大或重训；按完整 rollout 切 3/4 机阶段；持续开发集验收 |
| 最后 60 分钟 | 停止大规模更新，最终留出验收、兼容性测试、报告与模型打包 |

初筛开发检查约每 20 万 environment-step 或 15–20 分钟；完整开发矩阵只给候选，避免评价占掉多数采样时间。8 卡初筛最多 480 万 environment-step 是参考上限，不是硬性等慢任务完成的理由。

正式训练的步数由实测吞吐×剩余时间计算，预期可达数百万至千万级但不能事先保证。统一报告 environment-step（一次全队 step 计 1）与单机 transition（step×N），不要混用。

控制器接收总 wall-hours 和可选绝对 deadline，选更早截止点。若准备超时，压缩初筛/候选数量，仍保留验收时间；不要隐瞒超时或自动拖到第二天下午。

## 9. 筛选、续训放大与重训触发

开发技能分数 S=min(explore到访率/0.80, patrol入环率/0.80, patrol有效环带占比/0.70, relay本机有效覆盖/0.90, charge有效到站率/0.95)。同时报告每个指标与最弱编号，不用 S 隐藏问题。

### T+2 小时筛选

- 优胜：相对旧 Actor，explore 到访或 patrol 入环提升至少 15 个百分点，或已接近门槛；旧技能无明显退化；跨两种子方向一致。保留最多两类方案。
- 进步但偏慢：关键技能提升 5–15 个百分点，给一次课程/示范修正机会，并限定到 T+3.5 小时。
- 无进步/异常：奖励、数值、目标合法性或数据覆盖有问题，修一轮；重复 NaN、逻辑故障或旧技能大幅退化时停止该 trial，保留日志。

小预算失败不等于续训在理论上不可行，选择阈值只是本次整夜资源决策。记录实际梯度更新、课程曝光和有效样本量，不能在 Actor 还没解冻或未见 patrol 时宣告失败。

### T+3.5 小时自动转重训

若至少两类合理续训方案经过有效更新和修正后，关键技能仍比基线提升不足约 10 个百分点；或提升只发生在近目标、远目标/最弱编号仍失败；或所有候选因旧技能退化无法交付，则启动重训。

保留最有希望的一个续训分支，其余可用 GPU 启动：

- R1：P1＋随机角色，从随机 Actor 初始化，2 个种子；
- R2：P1＋教师 BC 初始化，再 PPO，2 个种子；
- 剩余卡给第二优胜/3 机适配/验收。资源不足时优先 R2，因为期限内可利用导航示范。

从头重训指从随机 Actor 开始，不是重置全部环境设定。继续保持原网络结构作为第一轮；没有受控证据不临时换大型网络。

## 10. 选模、验收与防退化

以配套 lowlevel_training_acceptance.md 为准。先达到技能门槛，再按任务效果与最弱分层选择 checkpoint；未通过者只能标记 candidate，不能命名为“成功交付”。

保存 actor_best_compliance.pt、actor_best_mission.pt、ckpt_latest.pt 和最终选中理由。不同候选不能各自改变成功判据。

整局比较包括：

1. 原始高层协议的兼容性结果；
2. 对新旧 Actor 都应用同一个“目标完成后更新”的任务管理协议；
3. 原始 590 条诊断重跑，仅用于历史可比，不能替代修正后的主验收。

不能把新 Actor＋额外动作控制与旧纯 Actor 比较为模型改进。所有主验收禁用 waypoint_assist/教师动作。

## 11. 服务器需要实现的入口与执行合同

建议新增 experiments/lowlevel_training/：

- train.py：PPO 续训/重训、Actor-only 初始化、精确恢复、课程、新奖励与角色采样。
- reward_v2.py、goal_manager.py、sampler.py：任务目标、事件去重、目标生命周期与合法分配。
- teacher.py、warmstart_bc.py：可选示范数据与热身，独立记录来源。
- evaluate.py：修正后的技能、受控字段、整局与分层验收。
- overnight.py：GPU/CPU 调度、阶段门、deadline、恢复与报告。
- checks/：契约、奖励去重、输入/权重一致、目标可达、buffer/GAE 边界的少量必要检查。

运行合同示意（入口实现并冒烟后才有效）：

```bash
python experiments/lowlevel_training/overnight.py --plan research_outputs/h200_night_plan.json --wall-hours 8
```

overnight 先检测路径、依赖、8 卡、权重哈希、语义版本和磁盘，建立独立 run_dir；数据和输出路径按项目根解析，不能把 /Users/... 或旧容器 /workspace/... 写死。

基础单卡 PPO 训练步骤不得依赖 one-api/base_url，网络不可用不阻止训练。

## 12. 必须保存的元信息与失败处理

- 每个 trial 的完整配置、版本/源码 hash、Actor/奖励/采样契约、GPU、CPU、seed、课程阶段、累计环境步。
- 初始旧 Actor 仅从原文件读取；不得覆盖 deliverable/model/actor_best.pt 或旧 run。
- checkpoint 包含 Actor、训练值网络、optimizer、ValueNorm、步数、RNG 和课程状态；Actor 部署文件仍是原有 state_dict 格式，metadata.json 独立保存。
- 原子写入，异常退出不读取半成品；每 10–15 分钟和阶段切换保存恢复点。
- Worker 错误/超时、NaN、shape 错误、显存不足和评价失败需检测并记录。自动恢复有次数上限（同原因最多两次），不能静默死循环。
- 短烟雾验证 Dummy/Subproc 一致、终止后不泄露 reset 状态的奖励、GAE 不跨 episode、goal 变更时势函数与事件正确重置、混合字段目标一致。
