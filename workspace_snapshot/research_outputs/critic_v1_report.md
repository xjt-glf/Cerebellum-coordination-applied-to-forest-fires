# EACC v1 报告：执行器感知反事实 Critic 的设计、训练与闭环验证

日期：2026-10-13（第二轮）
设计文档：[candidates_design.md](candidates_design.md)（三候选与选型理由）
代码：`experiments/critic_advice/{critic_data,gen_data,exec_model,critic_loop}.py`
数据与模型：`runs/critic_data_{exec,episode}/`、`runs/critic_models/`、`runs/critic_loop_*.jsonl`
结论范围：未接入真实 LLM（无外网；one-api 缺 base_url）；规划器为启发式 H；全部结论为"冻结 actor + H 规划器下的学习型建议机制"，不含"LLM 理解建议"的检验。

## 1. 方法：EACC（Executor-Aware Counterfactual Critic）

三层组件：

1. **执行模型** f_θ：输入 (态势实体特征 580 维, 计划 A=H 计划, 计划 B=候选编辑)，输出段末（20 步）**机制配对差向量**（40 维：每人员覆盖/AoI 族、每机 Δ能量/Δ位置、探索/发现/扑灭增量、窗口覆盖均值）。结构：标准化 + MLP(580→256→256→40)，3 集成。
2. **任务价值头** g_φ：输入 (特征 ⊕ 执行模型预测的机制差) → **整局** Δ扑灭格数（配对真值标签）。3 集成。
3. **建议机制**：每个重规划边界，H 生成计划后，参数化编辑空间（relay_assign / charge_now / explore_block / patrol_bind / release_relay / swap_roles / handover_off + noop）枚举候选 → 模型打分 → argmax（noop=拒答）。输出 = 定位（哪机哪编辑）+ 依据（预测机制差 + 证据串）+ 预测收益。

监督全部来自配对分支 rollout（同一快照、同后续协议、分支只在本段换计划）：exec 数据集（199 种子 × 双 regime，42889 条，20 步机制标签）、episode 数据集（80 种子 × 双 regime，~12000 条，整局任务标签）。部署期输入全部可观测（认知粗视图、人员位置/AoI/认领、能量、指令解析目标）。

## 2. 执行模型验收（预注册最小验证）

测试集 n=6527（按种子切分，同回合样本不跨集合）：

| 机制维 | pearson | RMSE vs 常数 |
|---|---|---|
| 每机 Δ能量（uav0-3_e） | **0.72 / 0.68 / 0.65 / 0.27** | 45 vs 65（−30%） |
| 窗口覆盖均值 cov20 | +0.42 | 0.122 vs 0.134 |
| 人员覆盖数 covered_count | +0.38 | 2.66 vs 2.86 |
| mean_aoi / high_aoi | +0.33 / +0.26 | 改善 |
| 每机 Δ位置 | +0.23~0.37 | 改善 |
| 探索增量 | +0.25 | 改善 |
| **信息层**（rknown/discovery@20） | ≈0.02 | 无改善 |
| 任务层@20（burned/ext/contained） | ≈0 | 无改善 |

有效维（27 维）宏平均 pearson **+0.230**；平面特征消融（仅全局+计划计数）**+0.155**。
**通过预注册门槛**：执行器响应（能量/位移/覆盖）可预测，且完整特征显著优于平面特征。

**预测边界的机制解释**：能量消耗是计划的确定函数（谁去充电/飞多远），可学；覆盖/AoI 是轨迹-人员几何的较确定函数，半可学；信息层（轨迹×火场相交）与任务层在 20 步内混沌。

## 3. 价值头 / 标量头（整局任务收益排序）

同一数据、同切分的公平对照（episode 数据 57 种子、test n=2299）：

| 头 | pearson | 顶 25% 预测的真实均值 | 底 25% |
|---|---|---|---|
| 价值头（特征⊕执行模型预测） | +0.112 | +2.22 | −0.66 |
| 标量头（特征直连，ReAd++ 式） | +0.133 | +2.77 | −0.59 |

标定单调；但**执行模型预测未带来排序增量**（预测噪声大，特征本身已含计划差异）。候选解释与后续用途：执行模型的独立价值应在(a) 机制层依据与解释、(b) 能量可行性约束（Δe 预测 0.72 最强）、(c) 闭环中 eacc vs scalar 臂的直接 A/B。标签均值 +0.42（完整编辑空间平均有轻微正效应，与一轮"规则编辑零均值"不同——v2 编辑空间更丰富）。

## 4. 闭环评估（60 种子/臂/regime，种子配对，runs/critic_loop_expl.jsonl / critic_loop_freq.jsonl）

基线绝对水平：normal ext 244.3 / cov 0.738；scarce ext 243.7 / cov 0.735。

**主闭环（6 臂）**：

| regime | 臂 | Δ扑灭 | 编辑率 |
|---|---|---|---|
| normal | random / rule / eacc / eacc_pos | −2.4 / +0.4 / −3.3 / −1.8（全 n.s.） | 1.00 / 1.00 / 0.95 / 0.77 |
| scarce | random | **−13.02±11.28** | 1.00 |
| scarce | rule | **−12.97±10.50** | 1.00 |
| scarce | eacc | **−13.27±11.56** | 0.92 |
| scarce | eacc_pos | −10.52±11.07 | 0.74 |
| scarce | scalar | **−17.25±11.68**（频率实验批次，出手率 0.92） | 0.92 |

**频率消融**（同臂降频到 1/3，或高阈值）：

| scarce 臂 | Δ扑灭 | 出手率 |
|---|---|---|
| scalar（每边界） | −17.25 | 0.92 |
| eacc_t3（预测>3 才出手） | −7.40±9.97 | 0.32 |
| eacc_rare（每 3 边界一次） | −3.93±9.77 | 0.31 |
| random_rare（同频率随机） | −5.30±12.04 | 0.33 |

**结论 C1（干预频率是一阶变量）**：损失随出手率单调放大（0.92→−17；0.33→−4~−7，入噪声）。降频收回约 2/3 损失。
**结论 C2（学习选择未超越随机）**：同频率下 eacc_rare（−3.9）≈ random_rare（−5.3）；离线 ~1-2 格的排序分离在复利中被淹没。
**结论 C3（"事后改计划"接口结构性失败）**：单次编辑标签均值 +0.5，但每边界复利为 −0.5/次——每次编辑都是对参数共享团队的扰动（改一架 → 全队观测变 → 全队行为分叉），30 次/局累积破坏协调。与一轮 P1 复现失败互为印证：正的单次效应不复利。
**结论 C4（普通 regime 饱和）**：所有臂 ±6 格内（n.s.），与一轮一致。

## 5. 消融（预注册）

- 去执行模型（scalar vs eacc）：闭环差异在噪声内；执行模型对 Δext 排序无增量（预测噪声 vs 特征已含计划差异）
- 去学习（rule/random vs eacc）：同频率下无差异——学习未提供选择价值
- 拒答价值（eacc_pos vs 每边界出手）：出手率 0.92→0.74，损失 −13.3→−10.5——**拒答的方向正确但幅度不足**
- noop 语义：训练集中 noop 真实标签恒 0（配对确定性）✓

## 6. 失败归因与 v2 方向

诊断链条：
1. 标签层：Δext@ep 单次标签被混沌主导（std 14），可学分离仅 1-2 格（多目标探针：Δext 0.04 / Δcov 0.28 / 机制层 0.3-0.7）。
2. 复利层：即使标签为正，"每边界扰动"的复利为负（C3）——接口问题不是模型问题。
3. 频率层：损害随频率线性放大（C1），学习选择无法在 +1-2 格分离下抵消 −0.5 格/次的扰动成本。

## 7. v2：建议对象换成"规划器"（oracle 探针 → 学习选择器 → 闭环）

v1 失败归因（§6）指向接口本身 → v2 把建议对象从"事后改计划"换成"规划器参数"
（建议语义 = "从现在起按此策略规划"，标签 = 切换后保持到回合结束的整局配对差，
持久语义）。

### 7.1 Oracle 探针（runs/oracle_switch.json，40 种子/regime，6 配置 × 5 切换点）

| regime | 最优固定配置 | oracle（种子内最优 cfg×切换点） |
|---|---|---|
| normal | P4b@400 +2.4（n.s.） | **+13.00±5.79** |
| scarce | 全部 ≤0 | **+11.78±5.45** |

**发现 V1（自适应空间有真实空间）**：规划器级切换存在 +12~13 格的条件收益（CI 不含 0），
且**只有条件选择能拿到**——固定配置全部无效（与二轮 P1 复现失败一致）。

### 7.2 学习选择器（runs/critic_models/switch_selector.pt）

特征 = 切换点上下文（与 H 计划同计划 A=B）；输出 = 5 个配置的整局 Δ；400 样本，
按种子切分，3 集成。离线测试（80 个切换点）：

| 指标 | 数值 |
|---|---|
| 每切换点收益（argmax>0 才切） | **+2.19** |
| 随机配置对照 | −0.31 |
| oracle | +8.59（拿到 26%） |

回归弱（每配置 pearson −0.44~+0.14）但 argmax 排序仍有选择价值。

### 7.3 v2 闭环（runs/critic_v2_loop.jsonl / critic_v2_once.jsonl，60 新种子/regime）

| 部署变体 | normal Δext | scarce Δext |
|---|---|---|
| selector（5 检查点可切换，粘性） | −0.25±4.88 | −0.58±6.95 |
| random_sw（同检查点随机切换） | ≈0 | +0.22±5.71 |
| **selector_once（仅 t=100 一次切换）** | **+2.22±4.42（n.s.）** | −2.90±6.41（n.s.） |

**发现 V2（离线-闭环鸿沟）**：离线 +2.19/检查点在闭环中归零。三个原因：
(a) 分布偏移——切换后轨迹偏离 H，后续检查点处于训练未见状态（训练 ctx 只来自 H 轨迹）；
(b) 单次切换语义的收益不随切换次数叠加（oracle 本身是单次切换）；
(c) 多次切换仍引入扰动。最干净的"仅一次切换"变体把 normal 拉回 +2.2 但仍不显著。

## 8. 本轮总结

**已实现并运行的系统**（全部真实训练/执行，无 GPU）：
- 执行模型（42889 配对样本，预注册验证通过：执行器响应可预测）
- 价值头 + 标量对照头（16104 整局标签样本）
- v1 闭环（6 臂 + 频率消融，60 种子/regime ×2）+ v2 闭环（oracle 探针 2400 局 + 选择器 + 单切换消融）

**主张—证据**：

| # | 主张 | 证据 | 强度 |
|---|---|---|---|
| 1 | 冻结执行器的机械响应可预测（能量 0.65-0.72、覆盖 0.42、位移 0.23-0.37） | exec 模型测试集 n=6527，平面特征消融 0.155 vs 0.230 | 强 |
| 2 | 信息层/任务层在段内与整局都不可从决策前可观测量预测 | 多目标探针 pearson ≤0.28；v1/v2 头 ≤0.13 | 强（在当前特征族内） |
| 3 | 自适应建议空间有 +12~13 格真实 oracle 空间，固定策略拿不到 | oracle_switch n=40×2，CI 不含 0 | 强 |
| 4 | 事后改计划的接口结构性失败：复利 −0.5 格/次干预 | 频率剂量反应（0.92→−17；0.33→−4）+ 学习选择≈随机 | 强 |
| 5 | 学习选择器离线拿 26% oracle 但闭环归零（偏移+不叠加） | v2 闭环 + 单切换消融 | 中（n=60） |
| 6 | 与 ReAd 的差异：ReAd 无执行器模型、无反事实、无拒答校准；但**在本任务上两者同样无法兑现收益**——差距是问题结构（混沌+耦合+复利），不是模型结构 | 全部对照臂 | 强 |

**对本项目的判断**：在"冻结 MAPPO actor + 启发式 H + 该环境动力学"下，任何以
"逐决策局部修改"为形态的建议机制都撞同一堵墙：单次效应被混沌淹没（±40 格、
与整局相关 0.008）、扰动复利为负、oracle 空间存在于不可预测的条件里。要兑现
oracle 空间，需要**决策前可观测信息之外的信号源**，候选：完整认知地图（非 10×10
粗图）、在线分叉验证（成本 10×，指南允许的"高成本独立方法"）、或大模型的世界
知识（阶段 C，需网络）。执行器响应模型（主张 1）是本轮可复用的正资产，也是
候选 C（证据约束 LLM Critic）里验证器的基础。

**下一轮优先级**：
1. 特征升级重测主张 2（完整认知图 + 关系编码）——排除"特征不够"这一最便宜的失败解释；
2. 阶段 C（LLM 闭环）待网络恢复：EACC 执行模型作为 LLM 建议的验证器（候选 C 设计已就绪）；
3. 若两者仍负：转向把"评估方法论 + 结构性负结果"作为可投 workshop 的贡献，
   方法主线改攻第二方向（延迟鲁棒性）或换 regime 设计。
