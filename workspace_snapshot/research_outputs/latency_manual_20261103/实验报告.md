# Codex 作为大脑：同步暂停与模拟推理延迟对照

## 结论

在一个种子的探索性实验中，固定 5 个仿真步的规划延迟与通信覆盖、信息时效下降同时出现，火情结果则有好有坏。这是值得继续研究的初步线索，但不证明所有场景都会如此，更不能当成统计显著结论。我们没有测量真实千问 API 时延，也没有测量 Codex 推理耗时；5 步是人为注入的受控设置，没有对应物理秒数。

## 实验协议

- 种子 975001、normal：4 架无人机、10 名人员，600 个环境步。冻结 Actor SHA-256 `dfa5cdd0f4b673567c04220af9d82ee55f16920d55398a02471a0d535d59982e`。
- 高层每 20 步观察并规划。本人逐窗口读取两组可观测态势，亲自提交 4 架无人机的完整计划和需要更新的人员任务。未调用外部大模型 API，未调用启发式大脑；人员不被明确指派时仍可能使用原本自动行为，安全充电和目标管理保持启用。
- A 在观测时刻立即执行新计划，相当于仿真环境在规划期间暂停。
- B 在观测后，先沿用旧任务运行 5 个仿真步，再应用基于旧观测制定的新计划；采用离线顺序推进来实现等价的固定步延迟，并非在真实墙钟时间中并行执行。首个初始计划在 t=0 两组一致立即应用，之后 29 次更新分别在 A 的 t=20,40,…,580 和 B 的 t=25,45,…,585 应用。两组均推进到 t=600。
- 大脑不读取真实火图、真实过火数及依赖真实火场分母的发现率；只读取已有可观测态势、已知火区、人员任务、状态、地图未知量。终局计算允许使用仿真真值作为评估。底层观测/人员寻路沿用现有实现，不宣称严格真实场景部分可观测。
- 同一个 Codex 会话同时看到 A/B，规划者未盲化且可能存在上下文污染；环境差异累积后两组独立选了不同计划，30 个窗口中有 18 个请求计划不同。并行成对同一 seed 不能排除规划选择带来的混杂。

## 主实验：分别对两组观测进行规划

| 指标 | A 暂停 | B 延迟5步 | B − A |
|---|---:|---:|---:|
| 步数 | 600 | 600 | 0 |
| 扑灭格数 | 236 | 231 | −5 |
| 过火格数 | 396 | 386 | −10 |
| 最终活火格数 | 2 | 1 | −1 |
| 合围数 | 5 | 3 | −2 |
| 探索率 | 86.30% | 83.62% | −2.68百分点 |
| 平均通信覆盖 | 69.63% | 55.05% | −14.58百分点 |
| 最终通信覆盖 | 100% | 90% | −10百分点 |
| 整局平均 AoI | 12.60 步 | 36.43 步 | +23.84 步 |
| 最终人员平均 AoI | 0.0 步 | 32.9 步 | +32.9 步 |
| 电量耗尽无人机数 | 0 | 0 | 0 |

注：扑灭、过火、活火和合围指标不是同一指标，不能只取有利单项判断总体更优。AoI 按项目中覆盖后重置规则定义，不能直接推导真实网络时延。B 的 29 个延迟窗口里，29 窗口有无人机位置变化、15 窗口有人员位置变化、15 窗口的人员已知火区列表发生变化、4 窗口覆盖率变化。这些是观测变化，并不自动证明相应计划已经失效或造成了损失。

## 补充对照：固定同一组 A 计划回放

为减少人为规划不同的影响，将主实验 A 的 30 次计划原样应用到两个新建回合：A 当时执行，B 除首条外延迟 5 步执行。A 回放与主实验 A 的关键结果逐项一致。因为 B 不再根据自身状态重新由 Codex 规划，所以该实验是固定计划序列下的延迟压力测试，不能代替实时大脑闭环。

| 指标 | A 暂停回放 | B 相同计划延迟回放 |
|---|---:|---:|
| 扑灭格数 | 236 | 234 |
| 过火格数 | 396 | 395 |
| 活火格数 | 2 | 1 |
| 合围数 | 5 | 4 |
| 探索率 | 86.30% | 83.57% |
| 平均通信覆盖 | 69.63% | 45.30% |
| 整局平均 AoI | 12.60 | 78.38 |

固定计划结果同样提示通信指标对延迟可能敏感，但两组偏离后，B 执行的计划并非根据 B 自己的状态决策，因此不能把这个差异直接视作真实异步决策的普遍效果。

## 复核和使用边界

同一过程日志 `seed_975001/decisions.jsonl` 包含每个决策时观测、计划、实际应用时刻和环境记录；`result.json` 是主实验终局结果。`matched_plan_replay.json` 是固定 A 计划的补充对照；`recorded_plan_replay.json` 使用原本两组各自计划重放并验证 A/B 关键指标完全复现。原始文件没有实际 API 调用和真实推理耗时。

本机从项目根目录运行（需要当前本机 Python 3.13、本地 venv 依赖和 `远端机器文件夹/experiments/feedback_attribution/joint_runtime.py`；后者在本实验只用新建运行时，不调用有问题的旧 snapshot/restore）：

```bash
# 校验并重放各自真实计划
PYTHONPATH=.venv/lib/python3.13/site-packages /Library/Frameworks/Python.framework/Versions/3.13/bin/python3 experiments/latency_manual/replay_matched.py --recorded-b

# A 计划固定时的 0/5 步延迟回放
PYTHONPATH=.venv/lib/python3.13/site-packages /Library/Frameworks/Python.framework/Versions/3.13/bin/python3 experiments/latency_manual/replay_matched.py
```

若要判断延迟是否普遍有害，需要更多独立种子、盲化或独立决策会话、不同仿真延迟以及真实耗时与仿真时间的明确映射，比较基于各自可观测态势的完整规划；并设置相同干预频率的强对照。
