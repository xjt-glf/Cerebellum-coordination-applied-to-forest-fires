# 给 H200 服务器 agent 的执行说明

请把本文件作为用户授权的训练任务执行：先阅读 research_outputs/lowlevel_training_plan.md、lowlevel_training_acceptance.md 和 h200_night_plan.json，再在当前项目上实现并执行整夜训练。

资源允许使用8张H200。定向续训优先；达到计划中的失败条件后自动转入重训。默认从开始实施起8小时，最后60分钟完成验收与交付；用户给出具体截止时间时以更早者为准，时间使用Asia/Shanghai。

当前新训练入口尚未实现。请先补训练包装器、目标奖励、角色采样、初始化/恢复、统一验收与overnight调度，完成短冒烟后直接运行。不要只执行旧train_lowlevel.py的--resume，也不要停在“计划已写好，等你指示”。

先处理计划第3节：修正受测机relay归因、探索目标合法性、首步记录、动态环半径评价，以及已经复现的target/rescuer_id混合字段编码不一致。不要重复前几轮大规模Critic探索。

保持原物理环境与9动作、355维观测、384宽2层Actor；旧权重不可覆盖。服务器使用Linux CUDA运行环境，不上传运行Mac的.venv。

充分利用8卡并行不同方案和训练种子，但按实际CPU预算分配环境worker。初筛后把卡转给优胜续训、适配和必要重训。资源调度与课程切换在文档授权范围内自主推进，不必逐阶段申请许可。

次日交付到research_outputs/lowlevel_training_final/：纯Actor权重、可恢复checkpoint、元信息、逐案例/逐回合验收证据、训练报告与复现命令。明确passed/provisional/failed，不能把训练结束当成模型达标；没有达标模型时仍按时交付最优候选和完整差距。

不用连接one-api，也不需要真实LLM参与本轮训练。完成底层验收即可结束，等用户审阅后再替换部署模型与重建Critic数据。
