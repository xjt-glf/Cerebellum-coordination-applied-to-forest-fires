## 2. 对指南优先级问题的回答（第一方向）

- **定位（哪条指令有问题）**：基准下唯一高频真实瓶颈是通信覆盖缺口（relay_uncovered 触发 373/1160 决策点）；能量（0-1 次）与巡逻（0 次）瓶颈不存在。定位谓词可从可观测证据（人员 covered/AoI/认领状态）构造。
- **依据**：正确的依据层级是**机制层**（本段窗口内覆盖/已知/能量变化，可配对验证、可预测）；任务层（扑灭数）在短窗不可承诺（主张 6/7），在整局由知识通道主导（主张 9）。
- **建议（具体改什么）**：基准饱和 regime 无建议价值（主张 5）；稀缺 regime（3 机/18 人）建议决策 ±10 格真实存在但方向随资源条件反转（主张 10）——"固定规则建议"被证伪，**状态条件建议**是必要形式。

## 3. 文献差异（对 ReAd 的修正性结论）

ReAd 的反馈形式（标量优势分 + 低于阈值重规划）在本任务上被证伪为无平均收益（eval_gating 的前提——随机计划+门限能改善任务指标——在饱和基准上不成立：门限筛选的"好计划"与任务结果无关）。与本项目 read_critic.py 自身的 TD 自举问题（指南事实 3/4）叠加，**标量分数反馈路线在本基准上没有可兑现的收益空间**。差异化主张应转向：可观测谓词定位 + 机制层校准承诺 + 整局任务验收（在稀缺 regime）。

## 4. 方向修正与下一步（按指南 §11 决策树）

本轮触发指南预设的两条分支：H 在常规场景始终更优 → 定位适用范围（已完成：稀缺 regime）；B 阶段收益判断依赖标签质量 → 修复评估口径（已完成：整局+配对+确定性）。

1. **换实验域**：稀缺场景族（3 机、12-20 人、3-5 火点，能量/通信同时吃紧）重建基线与筛选——那里建议决策有 ±10 格的真实方差。
2. **建议机制**：状态条件 Advisor（资源水平 × 覆盖缺口 × 火情分布 → 中继/感知配比的连续权衡），输出机制层承诺 + 不确定性声明；对标 always-rule / random / oracle。
3. **机制层预测器验收**：校准曲线、拒答后的负建议率、Δcov@20 预测的 per-regime 有效域。
4. **阶段 C（真实 LLM 闭环）**：需先恢复外网（webapp/server.py:104 的千问 key 当前不可达；且建议先移入环境变量）。
5. 第二方向（延迟）：暂缓。理由：同步等待下反馈质量尚无收益空间，延迟鲁棒性没有可检验的增量；若稀缺 regime 建议有效，再叠加异步协议。
