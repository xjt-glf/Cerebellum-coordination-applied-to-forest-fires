# 新 Critic 候选设计与选型（第二轮）

日期：2026-10-13　前置：第一轮阶段 A/B（[phase_a_audit.md](phase_a_audit.md)、[phase_b_screening.md](phase_b_screening.md)）
本轮目标：设计、实现、训练并验证适合本项目的新 Critic；read_critic.py / ReAd 只作为参考与对照。

## 0. 已有发现作为设计线索的正确解读

| 一轮发现 | 错误解读（本轮不做） | 正确设计线索 |
|---|---|---|
| 45 维特征 MLP 预测 Δext@60 失败（−0.09） | "神经网络学不了建议价值" | 特征里**没有执行器将如何响应**；且短窗标签本身被瞬态噪声污染。换标签层（机制量）+ 换表示（实体/执行响应），不是换更大的 MLP |
| corr(Δext@60, Δext@ep)=0.008 | "长期收益不可预测" | 短窗标签不可用；整局标签有效且由知识通道主导（corr Δrknown@ep ↔ Δext@ep = +0.47） |
| 改一架全队分叉（团队构成特征耦合） | "局部编辑无意义" | Critic 必须**联合建模**整份计划与执行响应，不能单机打分 |
| 固定双中继无稳定收益（复现失败） | "建议没价值" | 无条件规则不行 → **条件化**是必要的；稀缺 regime 存在 ±10 格真实方差 |
| 机制层半可测（Δcov20 pearson 0.54，粗糙特征） | — | 机制层是可学习层，且是任务收益的上游（rknown 通道） |

## 1. 候选 A：关系-时序交互 Critic（RIC）

- **解决的具体问题**：冲突定位（重复搜寻、覆盖缺口、补给争抢、交接冲突）需要建模多实体关系，ReAd 的平面拼接特征与 read_critic 的 45 维手工特征都没有显式关系结构。
- **表示与结构**：实体图（UAV/人员/火点簇/补给点节点，任务分配边）→ 消息传递 GNN / DeepSets 池化 → 每 UAV 问题类型分布 + 关系冲突边 + 编辑建议分布。
- **监督**：规则谓词做冲突类型弱标签 + 配对执行收益做建议价值标签。
- **建议生成与交互**：输出每 UAV 的"问题类型+建议编辑参数"，规划器据此局部修改计划。
- **相对已有方法的新机制**：显式关系归纳偏置；ReAd 无实体结构、无关系边、无执行模型。
- **失败风险**：①关系标签来自规则谓词=学规则本身（兜圈子）；②每决策点只有 3-4 机×10-18 人，图样本极小、训练数据多样性受限；③定位对了不等于编辑对了。
- **最小验证实验**：冲突分类任务上 GNN > 平面 MLP（同数据同预算）。

## 2. 候选 B：执行器感知反事实 Critic（EACC）← **本轮主实现**

- **解决的具体问题**：修改建议的真实价值取决于**冻结底层将如何执行它**——一轮实测 64.5% 的 explore 重定向在 20 步内零执行响应、"补中继"在饱和 regime 只加覆盖不加灭火、在稀缺 regime 反而有害。现有所有 Critic（ReAd 标量回归、规则谓词、随机重采样）都不预测执行响应。
- **表示与结构**（三层组件）：
  1. **执行模型** f_θ(态势实体集, 计划差异) → 段末**机制变化向量**（每人员覆盖/已知变化、每机能量消耗与位移、探索/发现增量，~21 维）+ 集成不确定性。DeepSets/池化 + MLP，CPU 可训。
  2. **任务价值头** g_φ(态势, 预测机制Δ) → Δext@episode（长窗任务收益代理）。
  3. **建议机制**：参数化编辑空间枚举 → f_θ 反事实打分 → g_φ 排序 → 校准阈值决定接受/拒答，输出 = 定位（哪机哪指令）+ 依据（机制Δ预测+不确定性）+ 具体编辑 + 预测收益。
- **监督信号**：配对分支 rollout（一轮已建好的基础设施）——同快照、同后续协议，分支 B=编辑计划 vs 分支 A=H 计划。机制标签=段末配对差（便宜，0.16s/分支），任务标签=整局配对差（2.4s/分支）。监督是真值不是自举。
- **建议生成与交互**：每规划周期，H 生成计划 → Critic 给出 0/1 个局部编辑（带依据与预测）→ 下发 → 恢复 H 协议。
- **相对已有方法的新机制**：
  - vs ReAd（标量 Q+门限重规划）：ReAd 不预测执行、不生成编辑、无拒答校准；EACC 显式反事实"若改成 X，执行将如何变，任务将如何变"。
  - vs 规则修复：规则无条件触发（谓词→编辑）；EACC 以预测执行响应为条件（覆盖零响应编辑、稀缺 regime 反向编辑）。
  - vs 同预算搜索：随机重采样无执行模型，采样分布与执行响应无关。
- **失败风险**：①执行模型学不出（机制层也混沌）→ 最小验证实验先把关：留出种子上 Δcov20/Δrknown20 预测显著超过 45 维 MLP 与常数基线，达不到就先修表示/数据，不进闭环；②机制Δ→任务Δ的映射断裂（一轮 corr 0.3-0.4）→ 价值头用整局标签直接训练（不是两阶段串联的假设，而是端到端头+机制辅助监督）；③闭环中"每边界一次编辑"叠加效应未知 → 闭环 A/B 直接测。
- **适配本项目的理由**：标签生成便宜（CPU 配对 rollout）、部署期输入全部可观测（认知图粗视图/人员位置/AoI/能量）、闭环评估协议一轮已建成。

## 3. 候选 C：证据约束大模型 Critic（LLM+EACC 验证器）

- **解决的具体问题**：诊断与建议的自然语言推理、对规划器的可解释交互；自由 LLM 反馈的幻觉与不可靠。
- **结构**：LLM 从结构化态势简报生成诊断+候选编辑（JSON）→ EACC 的执行模型做**反事实验证器**（预测机制Δ并筛掉不可靠建议）→ LLM 拿验证结果修订 → 下发。验证器由配对数据训练（与候选 B 共享）。
- **监督**：同 B；LLM 侧只固定 prompt 与结构约束。
- **新机制**：LLM 生成被学习型执行验证器**约束**（不是自由文本分数反馈——与 ReAd/A2C-LLM 的本质区别）。
- **失败风险**：LLM 不可达（当前：one-api 无 base_url、机器无外网）；代理 LLM 的结论范围受限。
- **本轮角色**：设计保留、组件复用 B（验证器即 B）；真实 LLM 可达后接闭环（阶段 C）。不作为主实现。

## 4. 选型决定

**主实现：候选 B（EACC）**；候选 A 的关系编码作为 B 的实体集合编码形态融入（DeepSets 即无显式边的关系结构）；候选 C 依赖网络，作为后续叠加。
理由：监督信号可靠性（配对真值）> 关系标签（规则派生）；数据成本最低；直接针对一轮实测的三个失败模式（零响应、条件反转、短窗标签噪声）；CPU 全流程可训可验。

## 5. 预注册的验证顺序（失败时的处理）

1. 执行模型留出集（按种子）R²/pearson 显著 > 45 维 MLP 基线 → 否则修表示/数据规模，不进闭环。
2. 价值头留出集 pearson > 0（整局标签）→ 否则换标签（Δrknown@ep 通道）或声明仅机制层。
3. 闭环（60 探索种子，双 regime）：EACC > random-edit 同预算 配对 95% CI 不含 0 → 再跑 60 新种子确认。
4. 消融：去执行模型（特征直连价值头）、去反事实（只评原计划）、阈值∞（never）、always-top（无拒答）。
5. 普通场景如实报告（预期饱和零收益，不挑选场景）。

## 6. 实验域声明（预注册）

- 稀缺 regime：3 机 / 14 人 / 3 火点（一轮显示建议方差 ±10 格存在的域）。
- 普通 regime：4 机 / 10 人 / 3 火点（指南基准，饱和预期）。
- 两 regime 同协议、同编辑空间、同预算；所有臂同一冻结 actor；结论按 regime 分层报告。
