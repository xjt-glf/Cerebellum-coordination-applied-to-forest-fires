# 人机协同场景：执行感知、跨时间尺度的反馈归因模型

日期：2026-11-01  
文档性质：**待实现、待训练和待实验验证的研究方案**。本文给出可执行的第一版路线，也说明哪些部分只是论文假设。适用于交给开发机上的 agent 实施。

## 1. 先回答：我们现在做到哪里了？

已经完成一个**由 Codex 人工逐窗口充当大脑**的人机联合规划演示：大脑每 20 步结合态势给无人机和地面人员下任务，冻结的 MAPPO Actor 执行无人机动作，人员控制器把任务转成作业点并复用原寻路/灭火逻辑。网页可以回放决策、人员任务和轨迹。见 `research_outputs/joint_agent_demo_20261026/README.md`。

准确地说，**已跑通一次人机联合控制演示；还没有训练出反馈归因模型，也没有证明自动接入的决策大模型能够稳定完成人员规划和采用反馈。** 目前 `brain=agent` 是由外部 Codex 在决策窗口提交联合计划；现有 `brain=llm` 分支主要负责无人机计划，两者不能混为一谈。

当前使用的冻结 Actor 是 `research_outputs/lowlevel_training_final/actor_selected.pt`，SHA-256：`dfa5cdd0f4b673567c04220af9d82ee55f16920d55398a02471a0d535d59982e`。原路径、权重与现有回放均须保留。当前仍采用既有几何通信与瞬时地图共享；**本方案不依赖新信道模型、传输速率或重训底层模型**。

此前 `research_outputs/critic_v1_report.md` 的旧 Actor + 启发式环境中，执行层某些量可预测，但任务层收益较难预测；频繁改计划导致闭环受损，离线排序结果没有稳定转化成闭环收益。这是旧配置下的实验证据，**不能直接套用为新 Actor + 人机协同的结论**。新方案必须重新采集数据并验证，禁止沿用旧标签直接宣称成功。

## 2. 要解决的问题和研究假设

大脑在 t 时刻同时决定谁侦察、谁中继、谁补给、哪些人员去哪里扑救；运行一段时间后看到覆盖下降或火势扩大，却不能仅凭“前后变化”说是这条决策造成的。可能是：

- **下发/执行环节**：指令未送达、被充电保护替换、人员作业点失效、无人机并未按请求执行。
- **时序环节**：计划刚开始，人员还在路上；补给暂时损失覆盖，但稍后可能恢复；此时不宜按最终结果打差评。
- **规划环节**：确实存在更好的可执行替代方案，比如调整中继服务对象、修正人员目标或分批补给。
- **证据不足**：火势变化、其他成员行为与后续决策共同作用，现有证据无法分清责任。

拟研究的问题：**在部分可观测的人机协同中，能否用一个学习型模型，把“请求是否被执行”“影响何时可能兑现”“相对可执行替代方案的效果”联合起来，产生有证据、可操作、可拒答的反馈，并最终改善整局表现？**

本方案暂命名 **HT-FACT：Human–UAV Temporal Feedback Attribution and Counterfactual Critic**。名称只是项目代号；“执行分支 + 多时间尺度 + 反事实 + 大模型”均可能已有先例，结构组合是否构成论文创新需要查新与实验，不能预设首次或保证发表。

### 2.1 结构的核心想法

```text
决策前可观测状态 O_t + 请求的人机联合计划 A_t
                       │
          ┌────────────┴────────────┐
          │                         │
  执行与交付分支 E              反事实效果分支 C
  指令能否下发/执行              A_t 与替代 A'_t 在
  人机进度、通信、能量          不同时间尺度上的效果差
          │                         │
          └────────────┬────────────┘
                       │
执行后可观测轨迹 O_[t,t+20] + 生效/抢占/取消记录
                       │
         时间与证据融合 / 承诺账本 M
                       │
反馈验证器：检查观测证据、校准区间、建议合法性
                       │
保持 / 等待 / 局部修正 / 请求重规划 / 证据不足
                       │
         决策大脑下一窗口使用
```

**角色区分：**这里的 Critic 是高层计划的学习型反馈模型，**不是** MAPPO 训练中估计价值的低层 CentralizedCritic。低层 Actor 继续冻结。可用小模型做结构化预测，语言模板或评价 LLM 负责表述；首个可复现实验不依赖第二个外部 LLM。

## 3. 先把输入、输出和信息边界定清楚

### 3.1 在线允许输入

以“每 20 步一次评价”为主时钟。每次记录 `episode_id, decision_id, tick, actor_hash, env_version, planner_version`，以及：

1. **计划前状态**：无人机位置、电量、任务、历史动作；人员位置、通信覆盖、AoI、当前任务/命令状态；充电站；无人机共享感知图、人员认知图、未知掩码、已知火区中心/规模/边界；上一窗口仍未结束的任务与年龄。
2. **请求计划**：每架无人机任务/目标/服务人员；每名人员任务、火区锚点、接近方向和可选航点；下发时刻与预期检查条件。
3. **执行证据**：计划解析后结果；`GoalProtocol` 和 `ChargeProtocol` 改写；人员命令 `issued/activated/expired/released/completed`、未送达/排队、受阻、撤离；每步或压缩轨迹、覆盖和能量的变化；实际触发的目标更新。
4. **20 步结束时可观测状态**：两张认知图、可观测指标和实际事件；过去的任务年龄、是否被新任务替代、下一检查时间。

信息边界：模型上线、提供给大脑的反馈、记忆检索使用**部署时可获得**的数据；未知区域保留未知掩码，不能把未知当无火。原环境中的共享、人员通信、执行信息是否在场景下可获取须逐字段标注。不能把仿真器真值火图、未来轨迹、真实整局结果、未来干预分支泄漏给在线输入，也不能把训练使用的真值标签原样返回大脑。

目前 `sense_state()` 有可能混入由真值计算的全局评价量；旧演示首个航点也受到已看过同一场景的经验影响。实现前要做字段级溯源，建立 **`observable_view` 与 `oracle_evaluation_view` 两个独立对象**，默认拒绝未登记字段。允许仿真器在**离线标签及评估**使用真值，但未来信息不可进入模型当时的输入。旧人员 BFS 和作业点安全检查仍使用现有环境信息，不能据此宣称完全分布式/无真值的真实系统；如要做严格部分可观测实验，需单独修复并重新验证该假设。

### 3.2 反馈输出：事实、预测和建议分开

```json
{
  "decision_id": "episode-7:t-120", "evaluated_at": 140,
  "execution": [{"entity": "person:3", "status": "pending_delivery", "evidence_refs": ["evt:ord31"]}],
  "maturity": {"status": "pending", "earliest_tick": 178, "next_check": 160},
  "observations": [{"metric": "covered_count", "before": 8, "after": 6, "window": [120,140]}],
  "alternatives": [{"candidate_id": "relay_uav1_person3", "horizon": 60,
    "effect": {"metric": "person_connected_steps", "estimate": 12.0, "interval": [-3.0,24.0]},
    "evidence_type": "model_estimate", "support": "uncertain"}],
  "diagnosis": ["指令尚未送达；单凭当前覆盖下降无法认定原计划错误"],
  "action": "wait", "patch": null, "valid_until": 160,
  "uncertainty": "较高", "evidence_level": "observation_plus_prediction"
}
```

例子只是协议样式，数值是虚构的，不代表实验结果。`alternatives` 的值默认是模型估计，不是假装已在线运行反事实。建议动作只允许 `keep / wait / local_patch / replan / abstain`。`local_patch` 只在通过合法性、有效期、安全和模型可靠性检查后送给大脑；**不直接覆盖充电保护，也不强制大脑接受**。第一版不输出虚假的 0–100 综合分；如后续需要展示评分，必须有预先固定的分项规则和校准依据。

## 4. 数据基础：用新 Actor 重新生成

### 4.1 训练数据从哪里来

不使用真实 LLM 大量采集训练数据。由代码中的启发式无人机规划器 + 地面人员启发式目标分配器生成基础轨迹，再用多样化候选编辑生成干预；人员始终走现有受通信约束的 `PersonnelController`。训练期不调用千问、Codex 或其他大模型；Codex 可在少量演示/诊断中亲自当大脑，不能把其人工挑选的单局结果当批量测试。

旧 `experiments/critic_advice/harness.py` 可借鉴其配对执行和直接计算指标的方法，但默认 actor 是旧 `deliverable/model/actor_best.pt`，旧 `Snapshot` 只明确保存环境与 Python/NumPy 状态，不能假定它已包含所有本轮运行状态。必须为新实验新建快照：**环境、人员控制器及其 pending/active/event 序列、每机订单、GoalProtocol/GoalManager/内部采样器随机状态、ChargeProtocol/目标站点、规划器内部状态、任务承诺、Python/NumPy/Torch 及环境独立 RNG** 一并可恢复；检查对象引用在恢复后指向恢复的环境。全局 RNG 的设置不能被并行线程互相污染，采集优先采用独立进程。说明实际捕获了哪些 RNG，而不是只在文档中声称捕获。

### 4.2 成对反事实：明确到底在比较什么

在时刻 t 保存完整快照，构造基准 A 和合法替代 A'：

- A：应用大脑原请求；A'：在同一快照只修改一项指定的人机联合计划内容。例如 UAV1 的服务对象从 P5 改为 P3，或 P3 的火区/接近方向改变，或某架无人机补给提前一个窗口。
- 两支都运行同一个冻结 Actor、人员执行器、目标管理、充电保护和时间终止规则。其他可变项保持一致，并保存随机状态。若人机控制新增状态导致配对不一致，先修快照；旧环境的确定性结论不能自动继承。
- 后续统一预先指定的策略 π，例如 **仅首窗口干预，t+20 后两支均执行同一个冻结启发式策略 π**；它是“同一映射”，两支状态不同，因此后续动作可以不同。另设 **固定计划保持 K 窗口** 协议，回答不同问题；不要混在同一标签中。
- 在 h ∈ {20, 60, 120, episode_end} 保存指标差向量 ΔY_h = Y_h(A') − Y_h(A)，并记录 h 是否因终止、任务取消或步数上限而删失。若某个里程碑发生得更早，再附事件时间，不把它伪装为固定时窗标签。
- 每个指标必须定义方向（例如扑灭格 A'−A 越大越好，过火格越小越好）、原始计数和分母。动态变化的认知比例须与原始格数/分母同时记录；`set_plan()` 会清 shaping 电位，配对指标从环境状态独立计算，**不要用 shaped return 当因果标签**。

此标签只支持：**在被测模拟器、当前快照、实际执行机制、候选修改、后续 π 与所列时域下的相对效果**。它不证明现实世界的因果关系，也不自动说明谁应承担责任。

候选由固定、可审计的生成器给出：无人机中继对象/位置、探索航点、分批补给；人员目标火区、接近方向、继续/增援/撤离。每个候选必须语法合法、目标可用/在界、人员 ID 合法，并保留不改计划 noop。避免只选择明显好方案；按场景覆盖收益正/负/接近零和未兑现案例。

**必做 noop 校验：**完全相同的 A/A' 从新快照分别运行 20、60、120 步与整局，比较逐步动作、状态、命令激活、指标、日志和 RNG。默认确定性配置下要求严格一致；若开启随机扰动，则固定共同随机数，分别解释何时要求逐步一致。任何不一致先停止采集修复。

### 4.3 初始规模：先做可行性，不用大模型堆样本

- 阶段 0 先用 10–20 个训练种子做快照及接口冒烟；每 seed 取多个不同任务边界，检查覆盖失联、长距离在途、扇区受阻、被充电保护抢占等。
- 阶段 1 建议从 **120 个训练种子、30 个验证种子、30 个独立测试种子** 起步，按完整 episode/地图生成种子分组，绝不按同一 episode 的窗口随机切分。每场景提取若干边界，每边界 1 个 noop + 4–8 个合法候选；先计算预算，再采集中短期全量标签，整局标签分层抽样而非盲目生成。具体规模可按采集速度调整，提前记录最终规模与耗时。
- 场景族至少有：常规 4 机/10 人；稀缺 3 机/12–18 人；改变初始火点数量与分布。若 Actor 在其他机数/人数下无法运行，应先查明观测契约，不能捏造泛化结果。
- 在收集到的随机种子之外，另留一次最终确认集；选择模型、候选生成器、阈值和所有提示词后再评估。重复使用测试集调参须重新建立最终确认集。
- 若观察到组内相关（同场景多个分叉），统计以**种子/整局**为独立单位，用成对种子 bootstrap 或成对检验；不得把成千上万窗口视为独立场景。

训练分支同样记录场景、actor 哈希、任务管理协议、人员控制器版本、配置、代码版本、种子、候选生成器和后续策略；复用已有运行文件前先验证其版本与统计定义。

## 5. 建议网络：三个分支如何真正工作

为避免“只把三个名字画在框图里”，下面给出实际的前向计算和训练任务。首版不追求大模型参数量；网络必须与 MLP 基线做公平对照。

### 5.1 共享表示：可观测地图 + 人机关系图

- 地图输入：100×100 多通道张量，至少包含无人机已知燃烧/非燃烧/未知、人员已知燃烧/非燃烧/未知、可观测障碍或有效位置掩码；未知不能编码为安全。使用小型 CNN 做空间编码，并用相对坐标或局部裁剪聚焦各实体/目标；输入以实际已有观测为准。
- 图节点：每架 UAV、每名人员、每个已知火区、每个充电站和任务节点。节点特征包含类型、位置、能量、当前请求/已执行任务、进度、已知信息、是否通信和任务年龄等；变长节点带 mask。
- 图边：UAV–人员的可观测通信状态/距离、人员–火区距离与目标关系、UAV–站点距离、计划分配边。用 2 层关系消息传递或图注意力得到实体嵌入，再做掩码聚合；保留实体级输出用于定位具体哪条任务。
- 时间输入：最近 K=4 个窗口的可观测事件序列，GRU 或小型时间 Transformer 编码；按 `decision_id` 关联承诺账本，保留时刻、状态和缺失 mask。不要给未来窗口。

建议初始维度：节点/地图嵌入 128，2 层图网络、GRU 隐层 128；训练与部署设置固定归一化统计（只由训练集拟合）。精确参数量、batch 和吞吐在实施报告中记录。节点顺序改变时输出应满足相应的置换一致性，新增或缺失人员要正确 mask。

### 5.2 分支 E：执行与交付

输入计划前的表示和每个实体的指令，输出未来 h=20/60 步每项任务的：指令是否收到/被覆盖概率；距离或有效进度；人员作业点可用性/被阻挡概率；覆盖步数、能量变化等。执行后追加**真实日志**，区分事实与预测：例如 `pending_delivery` 由事件事实确定，不能仅用模型猜测。

训练标签来自记录下的执行过程。连续目标用 Huber 或归一化回归损失；事件概率用带类别权重的交叉熵，缺失/取消/终止样本 mask 或明确删失处理。已观测到的执行事件不需要模型重复“预测”，模型用于预估未来或补充缺失，不得覆盖事实。

### 5.3 分支 M：成熟度和延迟收益

对每条承诺维护 `issued → pending_delivery → active → completed / cancelled / expired / blocked`，另记录实际接收时刻与替代关系。模型预测任务在不同时间内出现可检验结果的概率/时间分布，输出 `未到检查期、可评价、取消/删失、信息不足`。理论最短时间可作为特征或软约束：无人机以当前运动模型计最短可达下界；人员按现有速度和路径模型计算保守界，动态火障、通信、绕路会让实际时间更长。

训练用真实到达、覆盖建立、人员开始有效作业等事件时间；未完成、被中途改派、回合结束、未送达分别编码，不当作“失败”或“从未到达”。可用离散时间 hazard + 右删失似然，首版也可用分时段分类并配删失 mask。若“完成后多久看收益”没有可信标签，先做事件成熟度预测，不臆造收益已成熟标签；跨时间任务收益仍由 C 分支估计，整局证据在到来时回填账本。

### 5.4 分支 C：条件反事实效果

**关键防泄漏设计：**C 分支只使用决策前可观测状态 O_t、原计划 A、候选计划 A'、候选类型、固定后续策略标识和 horizon，不能输入“执行 A 之后才出现”的结果当作 A' 的可观测事实。对每个候选输出多目标效果向量 `ΔY_20, ΔY_60, ΔY_120, ΔY_episode`，以及不确定性和数据支持标志。连续预测可采用多头回归，配合 3–5 个独立训练的 ensemble；优先输出指标向量，综合取舍由预先固定的任务规则进行，而非事后挑有利单项。

效果预测使用配对 rollout 标签；同一 A→A' 的反转样本可作一致性检查，但 A'=A 时预测应接近零。可以增加 `f(A')−f(A)` 的共享参数结构，或对交换后的样本加反对称正则；动作编辑的合法性由代码验证。人机耦合允许 C 使用全图关系，而非把局部执行效果简单相加。

**执行后归因**：E/M 根据真实执行日志说明发生了什么；C 同时回溯给出在 O_t 下原计划与备选的估计差。两者经融合显示“事实 + 受条件约束的模型估计”，不把 C 的估计说成已证明的执行后个体因果效应；因为在真实执行后再以实际轨迹为条件可能引入后处理偏差。需要确认的样本，可以在离线保存的 t 快照上复算分支，但不能默认部署现场可以倒流重跑。

### 5.5 三分支如何组合，避免以前的误差传播

E、M 和 C 共享实体/地图编码，**各自有直接监督头**；E 的预测可以通过门控作为 C 的可选辅助特征，但不能唯一决定 C，避免执行预测误差一层层传到最终任务收益。其余比较两种融合：直接共享表示 vs 停梯度执行辅助；以验证集选一种并在测试前冻结。

可用总损失：`L = λ_exec L_exec + λ_time L_time + λ_cf L_cf + λ_cons L_cons`。各损失按任务观测比例归一、用 mask 屏蔽缺失；λ 与候选成本在验证集固定，不用测试集调整。实施时记录每个头的单独指标，防止一个容易预测的能量项掩盖无法学习的任务收益。

## 6. 反馈验证和大脑接口

### 6.1 验证流程

1. **事实校验**：每条陈述引用 `decision_id / order_id / 时间 / 指标`，数值来自日志；没记录的事实不能补写。检查当前时间与建议有效期。
2. **执行状态校验**：确认请求与实际应用、送达、覆盖抢占；任务取消、受阻与尚未到期应分别显示。
3. **候选与安全校验**：检查人员与无人机 ID、坐标、任务语义、充电保护、当前通信与现有目标管理协议；不能以修改 patch 绕开安全约束。人员指令未连通时只能进入等待队列。
4. **效果及不确定性校验**：候选支持不足、未校准、不同目标互相冲突、关键区间覆盖零或成本高于阈值时，输出 `wait` 或 `abstain`。阈值只用验证集校准；ensemble 方差不天然等于可靠置信区间，须用独立校准集或验证集做经验覆盖评估。
5. **作用范围**：反馈有效期不超过下一决策窗口，引用的目标、通信或火情发生重大变化则失效；失效不替代下一次规划。大脑可采纳也可拒绝，要记录“建议—采纳—实际执行”的链条。

首版输出可由确定性模板根据结构化字段生成中文，避免另一个 LLM 编造原因；如接评价 LLM，它只能选择/解释证据包内事实，所有数值与候选 patch 再由同一验证器复核。**验证器只能降低可检测错误，不能保证反馈正确。**

### 6.2 不用 RAG 也能完成第一版

承诺账本为当前 episode 的结构化工作状态：计划、执行与后续兑现按 `decision_id` 关联。它不是宣称已经实现的跨局经验库。第一版模型验收可不加 RAG；后续只把**有足够证据、带适用条件和反例**的条目写入长期库，隔离训练/验证/测试信息。RAG 是独立消融，不应与模型本体的收益混在一起。

## 7. 训练配置与资源

默认 CPU 多进程采集、单 GPU 训练；如果开发机有 8 张 H20，可通过多个独立采集进程或多个小实验并行使用，实际收益主要受仿真 CPU/内存与数据 I/O 约束。先跑吞吐基准，禁止为了占满显卡复制相同数据。不要改动原权重。

首版 PyTorch 参数：AdamW，学习率 3e-4、weight decay 1e-4、batch 128、最多 80 epochs、验证集早停 patience 10、梯度裁剪 1.0；按日志观察收敛后调整。3 个网络随机种子或 ensemble 成员；记录每次采集/训练实际资源和时间。参数是初始建议，不是保证收敛的神奇配置。

标签标准化与类别权重仅从训练集统计，验证集用于早停、概率校准和门限选择，测试/最终确认集只做预先确定的评估。不得将某个 seed 的反事实 A/B 分支拆分到不同集合；如同一场景参数家族来自同一底图，也要按底图/场景族分组，额外做跨场景族测试。

## 8. 实验怎么证明有效：分层验收

### 8.1 先看标签与执行链，没通过不得训练

- 新权重加载、原演示可复现，人员控制按 `issued → activated` 工作；失联时新指令排队，旧指令行为按现有协议保留。
- noop 双分支逐步一致；真实干预只变指定内容；同一决策 t 的状态哈希、请求、解析、改写、人物命令状态均可追踪。
- 缺失数据/取消/过期被正确分类，不把不可能 20 步到达的远距离任务标成失败。
- 线上输入泄漏测试：改变未感知真值或未来评估字段时，在可观测输入保持相同的构造测试中，反馈输入/输出不得因此改变。此为模块隔离单元测试，不暗示真实环境其他模块也不存在真值依赖。

### 8.2 离线模型评价

| 层面 | 核心指标 | 比较与注意事项 |
|---|---|---|
| 执行/送达 | 事件 precision、recall、F1、Brier，位置/进度 MAE | 对比“上一状态延续”、规则、MLP；按人/机、距离和场景分层 |
| 时间 | 事件时间 MAE（已观测者）、删失处理、不同时间段校准/生存曲线 | 与距离下界和固定 20/60 步阈值比较，不能把删失当失败 |
| 效果 | 各 horizon、各指标的 MAE、符号准确率、Spearman、分位区间覆盖 | 对比零差/noop、候选经验均值、平面 MLP；明确样本接近零时不应以符号正确率冒充性能 |
| 定位 | 找对未送达、被保护覆盖、受阻、在途的 F1 与混淆矩阵 | 事件事实可直接从日志计算，不把规则检测正确率冒充神经网络新能力 |
| 验证 | 数据字段引用准确率、非法建议拦截率、漏拦率、不同置信门限下错误建议率及覆盖率 | 人工抽样核对；展示 abstain–coverage 曲线，不只挑拒绝最多的点 |

对具体“规划错误”的标签，只能在预先限定的候选集合/后续协议下定义，例如某替代方案在该指标上实际提升超过预定最小有意义差值。**没有替代方案显著更好不等于原规划全局最优。** “哪些人/机造成效果”只能作为基于所测局部干预的条件解释，不能将团队互动效果相加后宣称精确分摊。

### 8.3 闭环分组：才是最终证据

所有组使用**同一冻结 Actor、人员执行器、环境参数、时间预算、初始种子、任务目标和评价指标**；每组独立从初始状态运行，区别仅在反馈机制。推荐：

- A：无反馈，大脑照常决策；B：原始观测/指标反馈；C：规则诊断反馈；D：普通 MLP 或标量 critic 反馈；E：三分支反馈归因但去掉时间分支；F：去掉反事实分支；G：去掉执行分支；H：完整模型 + 验证与拒答。
- 另比较 H 去掉验证器/去掉拒答；以及**相同干预频率**的随机建议或随机候选、固定每 3 个窗口反馈。所有“给大脑”的反馈文本长度、调用次数、延迟预算尽可能匹配，否则报告差异，不能把增加上下文当模型效果。
- 主要终局指标预注册：扑灭格数、过火面积、未合围活火格、已合围火区数；护栏：无人机耗尽、人员暴露/安全事件（若当前环境无可靠定义则标为不可测，不得杜撰）、人员信息覆盖/AoI。附加统计：平均覆盖、信息传递、首次响应/到位时间、干预次数、建议采纳率、后续取消/冲突率、耗时、推理调用次数和成本。先定义每个指标的计算代码与方向，并报告原始值及区间。
- 同种子 A/B 是初始条件配对，不是同一轨迹；干预后分支会改变未来状态。每臂使用相同测试种子与相同协议；以种子为统计单位，报告逐种子差值、均值/中位数和 95% 配对 bootstrap 区间，明确主要终点与多指标处理。建议至少 60 个独立测试种子做初步闭环，并依据试点方差预估样本量；如果不足以排除重要差异，结论写“未证实”。
- 先在**冻结的启发式联合规划器**做低成本控制实验：确保无人机和人员都按同一接口接受反馈或候选选择。然后在有可复现预算时，增加真实 LLM/Agent 联合规划与反馈采用实验；固定模型、温度、系统提示、通信协议和 token 预算，记录 API 模型版本和原始请求/响应。Codex 人工参与可作为展示或个案，不应与自动方法不同资源预算的单局结果充当统计证明。
- 主检验应包含不依赖训练时同一基准规划器的场景：例如训练数据由启发式生成，验证另一个固定规划器下的反馈是否仍可信。否则模型可能只学会纠正数据生成器的习惯。

有益反馈必须在**完整闭环**优于相应强基线，且不以耗尽/过火等护栏显著恶化换取单一指标。离线相关性、例子、候选 oracle 上界或一次演示都不构成证明；反之有害也要原样交付。

### 8.4 如何判断值得继续

- **阶段 1：执行事件可解释**——送达/抢占/受阻可通过事实记录可靠识别，时间成熟度相对固定窗口基线改善且校准可接受。
- **阶段 2：效果方向可预测**——对独立场景，至少在预先定义的非微小效果区间，候选排序或区间可靠性超过零差和简单基线；按不同情景展示效果，不只报告总体平均。
- **阶段 3：有用反馈能被使用**——固定干预频率下优于随机/规则，且相比无反馈在预注册主指标上有稳定正向配对效果，同时护栏可接受。
- 若阶段 1 有效而 2/3 失败，交付可靠执行诊断和失败分析，**不能把它写成成功的因果归因模型**；优先检查可观测特征、标签噪声、候选空间、分布漂移和干预频率。若所有方法都差不多，报告负结果或修改研究假设，不反复挑种子直到显著。

## 10. 开发顺序

1. **P0 审计**：确认当前工作区代码、Actor 哈希、旧回放仍可打开；核查实际观测与真值来源，写数据契约。
2. **P1 人机联合采集**：启发式联合大脑、标准日志、承诺账本、完整快照；先通过新 Actor noop 和人员控制测试。
3. **P2 基线与数据**：建立候选空间、采集种子分组数据、跑规则/零差/平面 MLP，先判定问题是否有可学习信号。
4. **P3 模型训练**：共享表示与三分支，逐头评价、校准、拒答，固定版本与阈值。
5. **P4 闭环对照**：启发式联合大脑低成本配对、做频率和各分支消融；确认效果及护栏。
6. **P5 大脑接入**：先给真实或固定版本决策模型提供结构化反馈，记录是否采纳；可选增加评价 LLM 和 RAG；最后用冻结条件复测与留出种子确认。
