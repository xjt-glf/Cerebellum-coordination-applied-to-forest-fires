# 人机协同、容量受限通信与任务语义：跨机器实施任务书

版本：1.1，2026-10-26。本文是交给开发机 Agent 的实施规范，不是已实现功能或实验结论。

本版新增最高优先级约束：**强化学习训练、训练数据生成、技能评估和开发集选模均采用程序化启发式高层与人员控制，不让LLM/Agent逐窗口当大脑，不消耗规划token。真实Agent大脑仅用于训练结束后的正式对比/演示。** 本约束覆盖旧版中“训练阶段可请Agent亲自规划”的表述。

项目路径一律相对仓库根目录；服务器上自行定位根目录，不依赖本文编写机器的绝对路径。用户只授权本轮编写此文档，本文编写期间没有修改代码、运行新实验或启动训练。开发机收到后按本文完成实现、验证、训练和交付。

## 0. 用户已经决定的事项

1. 大模型统一规划人员与无人机。人员采用“任务＋作业点＋可选稀疏航点”，复用已有寻路与灭火执行器，不训练人员策略。
2. 引入系统级路径损耗、共享带宽与容量受限的消息交付，通信条件必须实际影响认知更新与指令生效。
3. 增加任务语义表示和消息优先级调度；不要求本轮训练语义编解码网络。
4. 正式决策只读取本节点已感知或已收到的信息，完整真值只供仿真物理演化、合法本地传感和离线评估。
5. 人员新指令成功传达后才生效；失联继续旧任务，本地规则负责避险。
6. 空间和时间尺度由本方案确定，见第3节。
7. 用户最新补充：可以一步到位把新环境下的无人机强化学习重训纳入正式范围，不再把“永不训练”作为限制。优先比较迁移续训和从头训练，以证据选模型，不先认定哪种更好。
8. PPO训练与续训从头到尾使用启发式高层规划、程序化任务课程和启发式人员移动，训练/训练采集/技能评估/开发集选模均不接入LLM或文件式Agent大脑。执行Agent可以编程、监控和调整训练，但不逐窗口生成训练样本的高层计划。最终需要真实大脑的对比/演示才由执行Agent亲自规划，不默认调用付费千问API，不把启发式冒充Agent实验。
9. 开发机有8张H20。先CPU开发；确需训练时先用1张GPU和适度CPU环境并行。其余卡不是必须占满的指标。

## 1. 最终要完成什么

形成一个可运行、可解释、可复现的闭环：

```text
本地传感 → 节点本地认知 → 容量受限消息传输 → 指挥端认知
                                                ↓
                          Agent统一分配人员和无人机任务
                                                ↓
                           指令排队、传输、接收、验证、激活
                              ↙                       ↘
                  人员任务管理器＋BFS            无人机任务接口＋PPO
                              ↘                       ↙
                          执行进展、局部火情与通信反馈
```

必须同时交付网页演示、无前端运行器、通信/人员机制测试、新旧Actor对照、新策略权重和完整报告。不能停在只修改提示词、只显示速率、只提交代码或只启动训练。

本轮的研究对象是仿真中的人机联合任务规划与通信约束，不是人类行为心理模型、实飞飞控、完整5G协议栈或真实森林火灾标定。现有神经Critic的新结构、学习式RAG检索器和语义编解码网络不在本轮必做范围，保留接口即可，不得为此拖延主闭环。

### 2.2 必须处理的隐性信息捷径

以下不是可忽略的小问题，决定了新通信实验是否成立：

- `fuse_team_maps_partial()`当前默认`share_all_observations=True`，会即时全队融合。
- `update_communication_coverage()`进入半径就重置AoI，并用`np.maximum`融合地图。
- `rescuers_map_info`当前为全体人员共享，单个人看到的信息会自动成为全员已知。
- `team_map()`存在把各UAV地图直接合并的兜底。
- `build_obs()`的global字段含依赖真值分母的发现率/认知率、真实过火比例和火势变化；team/coord字段还读取其他实体当前真实位置、电量和任务。
- `_people_blocked_map()`、`_white_components()`和BFS读取整张真实火图，会使地面执行器提前知道远处障碍。
- 人员目标有全局再分配、周期再平衡和每5步换目标，中央指令很容易被覆盖。
- 旧网页`llm_full_state`默认打开；旧`compact()`会读取`true_fire_clusters`；旧简报还包含真实过火/发现率等汇总，删掉真值栅格本身不够。
- 当前人员灭火是邻域自动作用，而不是“失联就不灭火”。旧提示词中相关描述不正确，必须同步修正。

主任务是封住这些信息捷径，同时保留`legacy_v2`模式原样回归；不能直接全仓替换后导致旧实验无法复现。

新增默认配置名`joint_v3`，旧基准配置名`legacy_v2`。

| 项目 | joint_v3默认值／规则 |
|---|---|
| 地图 | 100×100，1格=10m，约1km×1km |
| 时间步 | 5s；600步=3000s=50min |
| 高层规划 | 每20步，即100s；事件触发可记录但正式首轮保持固定周期 |

| 人员移动 | 默认0.5格/步，即1m/s，保留浮点插值 |
| UAV高度 | 固定30m AGL，仅用于3D链路距离，不优化高度 |
| 基站/人员射频高度 | 固定2m／1.5m；与地形高程组合时统一同一坐标系 |
| 初始规模 | 4UAV、10人员、3初始火源；不修改既有初态生成分布来制造优势 |
| 基站 | 读取`env.base_pos`，不是充电站；充电站读取现有真实站点列表 |
| 感知/灭火/能量 | 先保留原格单位参数与动力学，记录其米/秒映射 |

坐标继续使用`[x,y]`和矩阵`map[x,y]`，距离换算先乘`cell_size_m`；通信使用3D距离。所有外部消息时间字段用仿真tick整数，展示可另转秒。单位和版本必须写入每个运行manifest。

## 5. 认知与真值边界：先实现这一层

### 5.1 节点与存储

每个节点独立维护`KnowledgeState`：基站`bs:0`、UAV`uav:i`、人员`person:i`。

```text
fire_map[x,y]               未知=-1，其余延用状态编码
observed_tick[x,y]          该条信息原始观测时刻，未知=-1
source_id[x,y]              原始观测源
received_tick[x,y]          本节点获得该记录的时刻
entity_tracks[id]          已知位置/电量/任务、生成与接收时间
orders_received            已成功接收的指令
delivery_receipts          已收到的ACK与任务进度
```

同一格的记录按`observed_tick`更新，时间相同用固定源ID顺序打破平局；不能继续按火势数值max融合，因为火势大小不是新旧顺序。旧消息晚到不得覆盖较新状态；转发不能改写原始观测时间。地图对象不允许不同节点共享可变引用。

每个UAV只在自身感知区域写入真值传感结果。人员只更新自身八邻域及本次实际作业结果。初始已知内容仅限任务公开先验：地图边界、静态地形（若声明为预装地图）、基站/充电站、编队与人员初始部署信息、公开风参数及设备能力。不允许在reset时暴露随机火源位置、真实火区数目/状态或未来信息。

初始部署位置来自共同任务先验，后续位置只能由本地传感/成功接收的遥测更新。人员之间默认没有“心灵感应”共享；本轮不加人员—人员无线链路，若扩展必须单独计容量。

### 5.2 三种对外视图

- `planner_observed_snapshot()`：仅基站已知内容及其时间戳，供正式Agent和启发式。
- `node_observation_view(node_id)`：本节点本地传感＋已收消息，供人员与UAV执行器。
- `oracle_snapshot()`：评估和调试，存独立目录；不得嵌入正式简报、提示词、事件或决策元数据。

正式大脑不得看到真实累计过火、真实召回率、未发现火区质心等oracle派生汇总。可以看到基站认知图估计值，字段名明确`estimated_*`；未知或过期不要假装为当前真值。

`team_map_info`和`rescuers_map_info`可保留为legacy/评估兼容字段，但不得成为joint_v3执行信息源。评估使用人员认知并集时必须标明是“oracle统计的并集”，不等于任何人实际拥有该图。

### 5.3 允许的真值读取

允许：火灾物理更新、局部传感器读数、候选实际移动的碰撞/本地危险判定、实际近距离灭火结算、信道物理计算、终局评估。禁止：远程任务选择、整图寻路、未知火区排序、给在线Actor/大脑注入oracle绩效。

本地避险可在紧邻传感范围更新危险并阻止进入真实燃烧格，但不得用整张真图计算一条预知未来障碍的路线。

## 6. 人员任务控制与旧执行器复用

### 6.1 联合计划契约

新增外层`joint_plan_v3`，不要破坏原`TeamPlan`：

```json
{
  "schema_version": "joint_plan_v3",
  "plan_id": "agent-seed-tick-counter",
  "issued_tick": 40,
  "uavs": [
    {"id": 0, "task": "explore", "target": [35, 42]},
    {"id": 1, "task": "relay", "rescuer_id": 2},
    {"id": 2, "task": "explore", "target": [70, 65]},
    {"id": 3, "task": "charge"}
  ],
  "personnel_orders": [
    {
      "order_id": "p40-west-1",
      "person_ids": [0, 1, 2],
      "task": "contain",
      "target_region_id": "observed-region-7",
      "target": [38, 43],
      "approach_sector": "west",
      "waypoints": [[33, 40], [38, 43]],
      "support_uav_id": 1,
      "valid_for_ticks": 120
    }
  ]
}
```

这是结构示例，不是应执行的固定计划。`person_ids`可批量写，但传输与生效按每个接收者分别计算，不能一次发给一人就全组生效。每人同一计划最多一条新任务。没有新任务时保持本地已有任务，不自动idle。

人员任务只实现`contain`、`transit`、`hold`、`retreat`。`contain`控制火区、外围作业区域和可选方向；不是让人员以火区质心作为必须进入的终点。最多8个稀疏航点，逐点验证，所有数字有限且在边界内。

`valid_for_ticks`默认120、上限300，从`issued_tick`计算绝对过期时刻，不从收到时重置。远距离转场可跨高层窗口；刷新相同语义任务不得清零进度。任务有效期与数据包TTL不同：过期指令拒绝激活并回传NACK，不能让晚到旧指令覆盖新指令。

`target_region_id`从基站已知火图生成，维护稳定ID与版本，不能使用每次按面积排序的数组下标。人员可以只收到目标区域描述而尚未收到精细火图，执行时仍受本地认知和安全检查约束。

### 6.2 人员任务状态机

```text
issued → queued/in_transit → received → active → completed
                             ↘ rejected/expired
active → blocked / holding / local_retreat / failed
```

维护`central_intent`（中央已发）、`pending_order`（网络中）、`active_order`（本人已收）三份状态。UI和日志不能把issued等同active。ACK也须传回基站，中央不知道尚未回传的完成状态。

优先级：本地紧急避险 > 已收到且有效的本地任务 > 任务内局部绕行/外围推进 > 允许的本地兜底。中央未交付的命令无权改变执行器。

需要处理旧环境的所有覆盖入口：初始目标分配、全局`assign_rescuer_targets_by_cluster()`、`rebalance_every`、`target_steps>=5`、`assign_next_target_for_rescuer()`、`no_fire_nearby`判断。有效中央任务不能被这些入口换成其他火区。任务内沿同一作业区域选下一个合法点可以保留，但必须记录为`local_refinement`，不是中央改派。

### 6.3 寻路和退化行为

复用BFS和浮点速度插值框架，但新接口须接收本人的认知图/阻挡图，不读取全局真实火图。未知格第一版允许谨慎探索：按当前认知规划，每步前依本地传感重新检查；发现障碍后局部重算。静态已知地形可作为预装先验。

- 普通行走保持原规则：不进入已知燃烧/烧尽/已扑灭格；紧急撤离可保留既有特殊处理并标记。不能为了训练变好随意放宽。
- 新BFS不得使用旧“目标即使燃烧也允许进入”的特例。作业点须在合法外侧；失效时在同一作业区域找替代点。
- 无路先局部重规划，持续20tick无进展后标记blocked并排队报告。不能静默切成其他火区自动分工。
- 已到达`hold`点不算卡住。停留、灭火、等待消息分别记状态。
- 通信中断不是停止一切：旧任务仍有效就继续；过期后仅进行当前区域内的本地作业/保持，紧急危险时撤离到本人已知的可达安全位置，不跨区自动接新任务。
- 不保证“0危险暴露”能在当前火势机制中做到；必须区分主动走入火格、脚下被火蔓延、紧急撤离，不得靠瞬移隐藏失败。

## 7. 无线信道和共享容量模型

### 7.1 第一版明确是系统级抽象

不实现射线追踪、OFDM、真实MAC重传协议或波形。默认采用对数距离路径损耗、噪声与速率抽象，再用时分共享约束实际消息服务。模型不声称经真实森林测量标定，不直接套城市3GPP场景冒充森林。

参考入口：ns-3传播模型文档 <https://www.nsnam.org/docs/models/html/propagation.html>。标准模型如需扩展，先检查场景、频率、高度和距离适用范围，本轮默认不要求实现全套TR 38.901。

```text
d_3D = sqrt((10Δx)^2 + (10Δy)^2 + (h_i-h_j)^2)
PL(dB) = PL(d0) + 10n log10(max(d_3D,d0)/d0) + X_shadow
P_rx(dBm) = P_tx + G_tx + G_rx - PL
N(dBm) = -174 + 10log10(B_Hz) + NF
SNR_linear = 10^((P_rx-N)/10)
R_link = η B_Hz log2(1+SNR_linear)
```

| 参数 | 默认值／要求 |
|---|---|
| 载频 | 2.4GHz，参考距离d0=1m |
| PL(d0) | 由自由空间公式随载频计算，约40dB；不要独立重复调两处 |
| 发射功率 | 所有节点先固定10dBm，不作为决策变量 |
| 天线增益 | 0dBi |
| 路径损耗指数n | 3.5，作为未标定系统级场景假设，不称为通用森林常数 |
| 噪声系数NF | 7dB |
| 实现效率η | 0.5；结果称为“模型有效链路容量”，不是实测吞吐 |
| 网络总带宽 | 默认20kHz，固定预注册压力档5/20/100kHz |
| 可用链路门限 | SNR≥5dB，低于门限数据不交付；配置中可独立禁用门限作诊断 |
| 阴影项 | 默认0；压力档采用σ=4dB的可复现空间相关阴影场，不做每次查询独立抽样 |

这不是Wi-Fi或5G标准参数组合，而是可审计的窄带抽象无线网络。必须在报告中写清楚。带宽档、生成负载和任务效果必须联合报告，不能看到Agent结果后挑一个最有利档位。

地形高度存在但尺度/地理标定不清；第一版默认平地射频高度，不擅自把CSV数值当真实米或遮挡损耗。地形用于信道时另开配置并说明单位，不把“有地形图”说成已实现传播遮挡。

### 7.2 单碰撞域TDMA，禁止容量凭空复制

第一版使用全网络单碰撞域，所有节点的数据发送共用同一频带。每tick 5s划分50个0.1s槽，一个槽至多一个发射动作；收发半双工。数据链路在被分配时使用全带宽，按实际占用时长计服务量。

- 消息按真实编码比特数推进，不用“有链路就整包完成”。
- 部分传输可累计，但任何业务消息只有接收完整且校验通过才触发认知/指令更新。
- 每跳分别消耗空口资源；转发不能一次穿过多个节点。默认同tick新收到的业务包最早下一tick转发/激活，确保阶段无顺序穿透。
- 带宽/slot/frame余量不能重复分给每个接收者。单播发送给10个人原则上计10份容量；允许广播的仅是明确定义的广播消息，不能所有业务都免费广播。
- 接收端不在有效信道条件下时暂停/失败，记录原因；不得把未传完包直接加入接收方认知。

### 7.3 邻居发现与转发

必须选择并固定一种轻量、可解释的网络协议，避免“路由器免费读取全图真值”。默认：

1. 节点发送64字节固定格式beacon，含ID、位置、高度、能量摘要、时间戳和序号；64字节已经包含该beacon协议开销。beacon用2kbps的稳健控制速率，只有物理链路足以支持时接收，槽数向上取整。
2. 每tick最多20%时隙用于beacon，节点ID轮转，预算不足时延后，不保证每节点每tick都广播。邻居表只由实际收到的beacon更新，10tick未刷新则过期。
3. 允许链路：BS↔UAV、UAV↔UAV、UAV↔人员、BS↔人员；默认无人员↔人员链路。
4. 收到最终目的节点beacon可直接发送；否则按照包内“目的节点最近已知位置”在当前已知邻居中选择严格更接近目的地的下一跳，固定距离/ID打破平局。没有合适下一跳则存储携带，不查真实目的位置绕过去。
5. 最大8跳；记录visited path防环；转发不修改原始时间戳。目的位置过旧、局部路由死角造成的失败必须报告，不能归为Actor能力不足。
6. 所有新指令包含在途业务消息内，UAV指令也采用同一交付机制，避免无人机中央控制成为无限信息旁路。节点本地安全保护不依赖中心链路。

防冷启动死锁：起飞前可以预装一份不含随机火情的固定启动计划，作为所有实验臂相同的任务先验。例如一架机先建立基站附近接入点，其他机按预设航点开始探索；具体航点写入配置、机号角色按seed轮换，不能读火源位置后挑启动点。有效中央任务尚未到达时，节点按该预装计划执行，完成后由本地observed-only目标管理器继续同类任务；不允许让所有UAV永久悬停等待一条本来就没有网络可交付的首指令。启动计划也记录为`preloaded_prior`，不能统计成Agent在线决策。必须单独测试“初始无端到端链路→自主移动/存储携带→恢复通信”的过程。

该路由只作为所有实验臂一致的基础设施，不是本轮创新。若实测其死角主导任务失败，可以替换为已有的本地链路状态路由，但路由通告必须计费，且对所有臂一致重新验证。不得使用全真值Dijkstra结果宣称观测受限系统可实现。

### 7.4 队列与有效负载

常规业务统一使用确定性JSON UTF-8紧凑序列化，`size_bits = 8*len(payload_bytes) + 256`，256bit作为固定帧开销。实际转发后的header长度变化也计入。不要只数信息字段、不数坐标/时间戳/指令文本。第一版关闭额外压缩，若启用压缩需所有臂相同并保存解码证据。

数据时隙按全体任务节点ID轮转分给发送者，发送者只从自己的可服务队列挑消息，空槽可以浪费并计入利用率。禁止中央调度器免费读取全部远端队列、尚未回传的任务状态来挑全网最有价值消息。若实现动态借用时隙，必须显式计入请求/授权开销；首版不要求该优化。

默认TTL：危险告警12tick，火图批次60tick，遥测12tick，ACK/NACK及进度40tick；指令网络TTL为`min(40tick, 任务绝对截止时刻−当前tick)`。任务激活后的寿命仍由原任务截止时刻决定。表中TTL是待验证的系统设计参数，所有对照保持一致，并在压力实验单列其影响。beacon使用独立的固定64字节编码，不能再叠加常规JSON帧开销，也不能将业务消息伪装成beacon绕过计费。

源消息至少包含`msg_id, kind, src, dst, created_tick, expiry_tick, seq, payload`。每节点默认1MiB队列；满载按过期、可替代旧数据、最低优先级顺序丢弃并记原因。在途同任务旧指令可被新版本标记obsolete，但不能倒追撤销已激活任务。

需要支持：`order`, `ack/nack`, `progress`, `telemetry`, `fire_update`, `hazard_alert`。

- 本地火图数据按实际观测区域生成，每tick一次批量，最多81格/批，记录坐标、状态、原观测时间、源ID。完整观察快照含“未变化但被重新观测”的新鲜证据，不仅传变化格，防止无法刷新信息年龄。
- 每个发送者对同一目标队列可合并尚未开始传输的旧地图记录，保留最新。不能用合并掩盖丢失过渡事件；危险告警单独保留。
- 地图向基站上报，基站按人员当前任务选择相关地图片区发送。额外向邻居UAV传图也必须生成计费消息，不允许暗中全队融合。
- 同ID重复包不二次应用，不计重复有效吞吐；已过期包丢弃；不得把ACK/心跳当火情更新奖励。

## 8. 任务语义与调度

### 8.1 表示与数据来源

语义实体：已知火区、人员任务、UAV任务、支持关系、通信需求、消息依赖。每个语义字段都记录来源和时间。任务摘要和区域聚类只从基站认知图/已收状态生成。

正式输入示例：

```text
人员组A：已确认执行火区R7西侧作业，最后状态距今3tick。
需求：目标区域火线更新尚未确认交付，有效期剩余8tick。
保障：UAV1为指定支持机，其链路质量报告距今2tick。
阻碍：转场前需更新目标区域局部地图；当前无法确认该条件满足。
```

这些是结构化任务含义，不是让大模型任意编写“火区威胁”等无证据结论。没有建筑/人员伤亡模型，就不能生成虚构的建筑威胁分值或救援成功率。

### 8.2 FIFO与语义调度两种基础模式

两者共享beacon预算、过期丢弃、去重、队列上限、路由和数据源，只改变业务队列的服务优先级。

- `fifo`：可服务业务消息按入队时间/ID排序。
- `task_priority`：本地危险与撤离消息优先，随后是即将到期的控制/ACK，再是当前任务关联的火情和状态，最后普通地图。每5个业务可服务槽至少1个给已等待的普通业务，避免永久饥饿。

组内优先采用“优先级类别 → 剩余截止时间 → 入队时间 → ID”的确定性排序，首版不要增加待训练语义打分网络。

火情与任务关联必须根据发送方已知任务和消息接收者需求，不从真实火图反算“这条消息实际会扑灭多少火”。这属于任务语义/任务导向消息调度，不等同于已实现神经语义通信编码。

### 8.3 信息交付与任务启动

人员`contain`任务至少要求：任务指令已收、目标在其已收到的区域描述内、当前局部运动合法。精细地图尚未传达时，可先转场到已知安全接近点；不能因为中央知道火区就瞬间给人员补齐地图。

人员即使没有中央最新状态，也可以继续按旧任务和自身局部感知作业。所有“等待某消息”的条件都须有超时和本地保持规则，不能制造永久等待死锁。

## 9. 统一每步时序

定义逻辑状态在tick边界生效，建议如下：

1. 激活上一tick完成交付且未过期的新指令/认知；生成需回传的ACK。
2. 在规划边界，给当前规划器基站的observed snapshot；训练时规划器是程序化启发式，正式Agent实验才是Agent。新计划仅入队，不直接`set_plan()`全队。
3. 按各UAV已激活任务构造本节点观测，Actor产生动作；人员由本人已激活任务和本地感知产生路径步骤。充电保护和人员紧急避险记录为本地接管。
4. 结算移动、能量、充电、人员灭火和火势，遵循既有动力学，旧模式时序保持不变。新模式具体传感/灭火次序写入manifest和测试。
5. 各节点采集允许的本地传感/进度，生成消息。
6. 以当前物理位置计算本tick信道，执行共享beacon和业务时隙；本tick完整收到的消息进入`delivered_pending`，下一tick应用。
7. 保存节点、任务、链路、队列、动作和oracle评估；推进tick。

禁止人员列表/UAV列表遍历顺序导致消息同tick级联到全队。最后一个tick完成交付但尚未激活的包保持pending，评估不得额外白送一个通信轮。

正式初轮Agent思考期间暂停仿真，记录wall-clock时间，不据此声称解决真实异步推理延迟。新网络已有仿真传输延迟，但这与LLM推理延迟是两件事。

## 10. Agent亲自当大脑的运行协议

本节仅适用于训练完成后的正式Agent对比/演示，禁止在PPO批量环境、训练样本生成、训练期整局检查和开发集选模中启用。训练脚本不得等待`command_*.json`。

新建桥，不直接运行旧`compact()`。每个实例独立目录，例如：

```text
run_id/agent_io/request_000040.json
run_id/agent_io/command_000040.json
run_id/agent_io/accepted_000040.json
```

请求含`run_id, seed, tick, request_nonce, observed_snapshot_hash, schema_version, allowed_state, previous_delivery_feedback`。命令回传同一组身份字段、联合计划及简短依据；身份/hash不匹配拒收，不能读到其他seed计划。

执行Agent必须真正读取每次请求，亲自决策并提交。不得预生成固定90条计划然后自称在线大脑；不得调用未来快照、oracle评估文件、候选未来rollout搜索辅助正式规划。

启发式仅作为明确标记的对照臂和训练任务采样器。Agent超时/失败时停到可恢复检查点或继续本地旧任务并标记该窗口失败，不自动改用启发式后仍计为Agent正式局。不得长时间忙等，运行器支持暂停、保存和恢复。

Agent允许使用当前observed state做确定性统计、距离和队列分析，但这些工具对照臂应能使用，不能泄漏不可见未来。Agent会话中若已经读过某个holdout的oracle结果，此seed不能再当未见测试。

网页提供`agent_file`模式和待提交状态。页面显示可以选择oracle图调试，但正式Agent输入接口绝不能读取该展示层。不要默认连接千问，也不在报告、配置副本或日志中复制API密钥。

## 11. Actor适配、奖励设计与训练决策

### 11.1 采用三个明确身份的Actor候选

- `A0_legacy_frozen`：原355维Actor，通过observed-only适配视图运行，作迁移基线。不能为了保性能继续给它真值、即时共享地图。
- `A1_transfer_v3`：371维Actor，从旧Actor迁移后在新环境续训，首选候选。
- `A2_scratch_v3`：相同371维结构随机初始化，至少一个独立种子作为对照；是否扩大训练取决于早期趋势。

最终不能只因为A1优于A0就声称新算法有效。环境、信息口径和训练预算变化都要报告。A0适配失败可解释为分布偏移，不能直接说旧PPO训练错误。

### 11.2 先消除真值输入，再扩展通信观测

355维基础块仍保留原字段顺序和归一化，但数据改从本节点视图生成。每节点缓存键必须包含`node_id, tick, knowledge_version`，不能给4架机复用一份全局实时缓存。

- local/coarse/frontier/fire：自身图＋已交付图，不读全局并集。
- 人员/队友目标：本地传感或已收遥测的最后已知位置；缺失时使用既有缺省值或明确的未知占位，不能回退到env真实坐标。
- team/coord：已知历史报告；初始任务先验可预装，后续更新通过消息。未知字段及其年龄记入诊断，不假装完整。
- 真实发现率、真实过火率、人员真值认知率、真值fire_diff：从在线actor视图移除。A0缺失字段统一0并明确是兼容占位，训练A1/A2时可改用定义清楚的可观测代理值，但需版本化和一致实现，禁止混名。
- AoI改为有来源的实际交付/知识新鲜度；旧“半径外步数”仅保留`legacy_out_of_range_ticks`诊断名。

新增16维`radio_v3`，总观测371维，保持动作9类、hidden384、两层MLP，暂不为此任意重设网络：

| 索引 | 通信特征（从本节点已有信息计算） |
|---|---|
| 0–1 | 当前已探测的基站直连有效标志、模型容量归一化 |
| 2–3 | 当前任务目标接收方直连有效标志、模型容量归一化 |
| 4–5 | 该目标最近已知业务需求速率、已知服务/需求比例截断值 |
| 6–7 | 自身总发送队列bits、控制队列bits归一化 |
| 8–9 | 最老控制消息等待时长、距最后有效ACK时长归一化 |
| 10–11 | 已发现邻居数、目标遥测年龄归一化 |
| 12–13 | 本机可知窗口内业务截止期满足比例、近期自身数据空口占比 |
| 14–15 | 目标通信反馈是否仍有效、目标是否在本地观测范围内 |

容量特征用`log1p(R)/log1p(R_ref)`等固定配置归一化并截断，`R_ref=1Mbps`；时间/队列分母固定写入配置。非relay任务无目标时对应特征置0和valid=false。该表是最小实现要求，若发现特征冗余可在版本文档中调整，但不能临时访问oracle补值。

物理信道可由仿真内部真位置计算，但在线容量特征必须限于当前已实际探测/最近报告的链路，未知远端链路不能凭空传入Actor或Agent。

### 11.3 迁移初始化

旧网络第一层有输入LayerNorm，不能只给Linear加16列就声称完全等价。建议：

1. 355维旧块和16维通信块分别归一化后拼接。
2. 旧355维LayerNorm和第一层旧355列权重原样复制，新增16列初始0；后续层和head复制。
3. 新通信块使用独立LayerNorm或固定归一化，标明结构，保持新增列可学习。若拆分LN，需测试新特征为0时旧模型logits数值一致或在明确容差内。
4. A2采用与A1最终相同结构；中心化价值网络输入`own, mean(others), global`随观测维数适配，优先重新初始化价值网络，不把其warmup误称Actor无效。
5. 旧355维入口仍可加载旧权重。不同版本checkpoint必须带obs_schema和网络配置，拒绝静默截断/补零加载不匹配权重。

中心化价值网络遵循CTDE：训练时可以使用明确标记的oracle global state帮助估值和计算回报，但该张量不能进入Actor、在线Agent、调度器或人员执行器。最终部署只加载Actor。保存训练/部署张量通路图并测试隔离；“正式在线无真值”不等于禁止训练期特权价值网络。

### 11.4 奖励不能只最大化速率

不使用`reward += sum(R_link)`作为主通信奖励。否则靠近基站、传重复内容、制造无用流量都可能占优。

保留探索目标进度、指定目标执行、充电/安全和合理任务贡献，新增：

```text
r_useful_delivery     完整交付、未过期、去重后、与接收者当前任务相关的信息
+r_deadline_service   有业务需求时满足截止期/服务要求，避免无需求时白拿分
+r_deficit_reduction  任务接收者的已知服务缺口下降（条件化于本人任务）
-r_expired_control    关键控制消息过期或超时
-r_stranded           电量耗尽/无法返航等安全项
```

奖励可在训练时使用环境真值计算客观绩效，这不等于在线Actor可看到真值。信息价值类别须根据已知任务定义；不许用未来真实灭火收益作为在线调度输入。

实现要求：每个奖励分量单独记录；有效信息按唯一`(recipient,source,observed_tick,entity/cell)`计一次；ACK/重复包/自造心跳不刷奖励；“人员本地观察”不能冒领为UAV交付；无业务窗口不因吞吐为0扣分。

PPO每个物理tick的奖励统计只用该tick新发生的事件。一个包由多个relay转发，团队有效交付只计一次，若分给转发机则总信用守恒（首版均分实际路径UAV即可，方案固定）。不在本轮引入待研究的复杂反事实Critic来解决训练信用分配。

奖励权重先在CPU固定轨迹/简易控制探针上做量级分解：合理服务优于悬停刷分，重复传输不获利，充电安全不会被短期吞吐压倒。用各项实际分布定尺度，再用少量训练调优；不得在最终测试集上调权重。

“更晚观测到相同内容”不自动产生无限新价值。默认周期状态需求最多每5tick产生一份可奖励的新鲜度需求，重要内容变化/危险事件可单独触发；任务改名、重复下同义指令或发送额外心跳不能增加需求总量。每个接收者/任务对象/需求周期最多结算一次同类服务收益。需求生成规则是环境/任务公开规范，对所有方法一致，不能让Actor通过制造流量自我奖励。

### 11.5 训练流程和GPU限制

环境机制与泄漏测试通过之前禁止启动长训。先跑几十秒采样性能和GPU利用率，不因有8卡就开8份大量CPU环境。

推荐阶段：

1. `T0`：CPU验证观测、奖励分解、收集固定技能探针。
2. `T1`：A1迁移模型训练，Actor/价值分别监控；价值网络可先warmup，随后全部正常训练。
3. `T2`：A2从头训练的短预算对照，预算与A1累计环境步记录一致，不比一次短随机模型就下结论。
4. `T3`：较优路径补第二个独立训练种子；若两条都无效，先核查协议、信道可达、奖励漏洞和采样多样性，再调整。
5. `T4`：开发集选checkpoint，冻结后留出评估；保存可恢复训练状态。

资源默认：一次1张GPU；环境数先16/32测吞吐，CPU worker不超过实际可用核数。若两条对照并行、CPU仍有余量，可用第2张卡；使用更多GPU需有吞吐实测收益，不以卡数当完成度。不要求训练大语言模型。

课程：先固定/缓慢移动人员的可达单目标与轻通信负载，再加入人员任务转场、多UAV拥挤、带宽压力和失联恢复。角色随机化、指派机号随机化、多个环境独立随机种子，保留不同远近目标。不能再次把角色固化到机号。

初始诊断预算：A1和A2分别先约0.5–1M环境步检查趋势，而非承诺该步数必然收敛。若技能持续改善，可扩至约3–5M再评估；若无趋势不盲目烧满预算。完整记录实际步数、环境并行数、wall-clock、GPU/CPU占用和终止原因。

训练批量环境**必须**使用明示的随机任务课程/启发式联合规划器，不接LLM，不接文件式Agent。BC热身若确有需要，只使用确定性教师/启发式生成的数据，不新增Agent决策采集，不以“生成专家轨迹”为名额外消耗token。需要真实大脑的最终对比/演示留到选定模型后进行，不能据启发式训练轨迹声称Agent已参与。

#### 11.6 训练期启发式人机控制的明确要求

训练配置至少显式包含以下等价选项，并写入manifest（字段名可按实现调整）：

```yaml
phase: train
brain_source: heuristic_joint
personnel_controller: heuristic_approach
allow_llm_planning: false
allow_agent_file_brain: false
collect_agent_bc_data: false
```

高层训练规划器每20tick用基站已知信息给UAV分配探索、中继、充电，配合课程随机化近/中/远目标、角色、机号和任务持续时间，避免只学会单一种启发式分配。常规训练期eval和checkpoint选模也采用该配置，不要求Agent在线参与。

人员启发式具体行为：

1. 基站已有已知火区时，按到已知合法外围作业区域的估计距离分配人员，并保留简单名额/负载均衡，避免所有人挤同一火区。
2. 生成`contain`/`transit`等正式人员指令，仍通过本方案消息队列交付，不能直接改所有人的坐标或active任务。
3. 指令收到后，人员用本人认知图和已有BFS逐步靠近火线外侧；到位自动邻域灭火，再在该任务区域内选下一个合法外围点。
4. 未收到新指令时继续旧任务；本人局部发现火情时可在原任务范围内就近作业。既无任务也无已知火情则待命，不朝真实未发现火区导航。
5. 训练早期允许可复现的轻负载、固定/慢动人员、预装简单任务课程，后续必须恢复真实通信交付、动态人员和带宽压力。若某课程使用理想通信，须单独标记、不得充当新环境最终验收。

训练期的启发式与最终大模型使用同一指令契约、人员执行器和网络入口。区别是“由谁生成计划”，不是“启发式能瞬间控制人而Agent必须等待消息”。课程随机化不能绕过人员速度、碰撞、安全和信息边界。

省token验收：训练与选模日志中`llm_planning_calls=0`、`agent_planning_windows=0`、`external_api_calls=0`，且无等待Agent文件的线程。训练入口若收到`brain_source=llm/agent_file`应直接报错，不悄悄连接接口。记录中的0只指仿真规划调用；执行Agent编写代码、分析曲线和监控训练仍会使用其正常会话token，不能宣称整个开发任务零token。

遇到NaN、观测越界、奖励刷分、任务未交付却生效、不可达初态、训练环境同seed克隆等问题，保存失败证据并修复后重开有效批次；无效数据留档，不能混入最终报告。

## 12. 网页与运行接口

保留旧网页流程，新增模式选择与状态显示：

## 13. 测试、验收和判定标准

### 13.1 机制级必过项

至少以下测试要自动化，并用小地图避免昂贵训练：

1. 无链路时指令只在队列，人员/UAVactive任务不变化；恢复链路后完整收到且未过期才生效。
2. 同组3人仅1人收到时，仅该人改变任务。
3. 旧包晚到不覆盖新图；同ID重复包不重复应用/奖励；相同序号不同payload拒绝并记录。
4. 每tick空口占用不超过5s，beacon预算不超过20%；多跳每跳计费，无同tick业务级联。
5. 已传一半的包不更新地图；断链不会伪造完成；过期任务不能通过重收刷新寿命。
6. 未收到某火区信息的人员/基站/UAV保持未知；人员A本地发现不自动出现在人员B的图里。
7. 固定各节点可见状态，改变远处未观测真值后，Agent输入、人员路径计划和Actor观测/动作保持一致；局部传感或真实物理结果改变时允许之后产生差异。
8. 观测构造和寻路在测试代理下禁止读取未授权oracle字段；逐字段提供来源清单。
9. 有效中央人员任务跨越5步和rebalance周期不被旧逻辑覆盖；局部避险后仍保留可恢复的任务意图。
10. 已知障碍绕行、未知障碍局部发现再重算；不允许燃烧目标豁免导致主动走入火区。
11. 基站不是充电站；任意真实充电站可用；充电保护不依赖消息交付；不改写Actor普通运动动作冒充技能。
12. 进展/ACK晚到时基站仍显示最后已知状态，不直接从env读取“任务已完成”。
13. 同seed/config/显式计划重放时消息顺序、动作、地图和指标可复现；阴影场/RNG、队列和未交付包随checkpoint保存。
14. `legacy_v2`同动作回归无变化；两个模式缓存、随机流和节点状态隔离。

### 13.2 技能验收：先排除任务本身不可实现

开发、训练、测试seed分离。技能留出集至少20个场景，每个场景覆盖4机号及不同距离/负载，不用一个极易场景宣布完成。

| 项目 | 目标与口径 |
|---|---|
| 探索目标到访 | 合法目标，距离相关窗口`min(160,2*d_cheb+20)`、5格到访半径，≥90%；按近/中/远与机号分列 |
| 区域信息获取 | 同既有可复现区域完成定义，≥85%，注明感知与传回基站是两个指标 |
| charge | 足够初始返航余量、真实站点，≥95%；不混入本就不可达的初态 |
| 中继服务 | 在几何/带宽可实现的固定或缓动目标任务上，≥85%窗口完成指定有效消息截止期；另报链路到达和持续服务，不能用进半径替代 |
| 人员指令语义 | 完整收到合法指令后的正确任务激活≥99%，例外必须是明确安全覆盖/失效而非解析随机行为 |
| 人员运动 | 可达静态场景按速度和距离给窗口，≥95%到目标；动态火场不强行用同阈值掩盖不可达性，报告失败分类 |

中继“可实现”参考上界只用于离线标注/分组，不给正式策略。队列超载或网络断开时必须单列不可服务需求比例，不把物理不可能的服务一概记成Actor技能失败。若接口错误或路由死角占主导，先修环境，不加训练步数。

### 13.3 对照实验

旧三局/十局数据只作历史背景，不能与joint_v3均值直接拼接宣称改进。

最小对照：

| 臂 | 人机规划 | 调度 | 信息 |
|---|---|---|---|
| H-FIFO | 规则联合任务分配（含人员，不是旧仅管UAV的规则） | FIFO | 相同observed-only |
| A-FIFO | 执行Agent逐窗口规划人员与UAV | FIFO | 相同observed-only |
| A-SEM | 执行Agent逐窗口规划人员与UAV | task_priority | 相同observed-only |

三臂采用同一个已选定Actor、路由、业务生成规则、带宽、初态和预算。H-FIFO不得使用真实未发现火区。先3个开发场景做烟测，再在至少3个未用于训练/调参的配对seed完整跑600步；n=3只作描述性结果，不能报告“显著优于”。有时间再扩展种子，不提前保证优势。

Actor选择单独在固定任务课程/开发集比较A0、A1、A2，不把“换Actor”和“换规划器”揉在一个因果对照里。若需要人机联控贡献，可加Agent仅管UAV、人员自动本地分工的消融，但不要先膨胀成大规模全因子试验。

不同调度下的Agent应读取各自真实已交付状态重新规划，不能把A-SEM未来指令固定重放到A-FIFO后当作另一个自适应Agent。固定计划重放可以作机制测试，必须单独标记。

### 13.4 需要交付的指标

- 任务：累计过火、烧尽、扑灭、未合围燃烧格·步、600步截断合围时间及完成局数、探索率。
- 认知：各接收者真实燃烧格·步加权召回、任务区域知识新鲜度；人员平均与最差值，基站与人员分开。
- 通信：实际新鲜有效业务吞吐bits/s、模型链路容量分布、各业务交付率/截止期满足率、指令激活延迟、丢弃原因、转发开销、队列积压、空口利用率。
- AoI：每个业务流/节点最新已交付有效源记录的生成时间与当前时间差。无新更新不能归零；火图事件/周期状态流分别定义，初始无样本记unknown并报告可用率，不能默认完美新鲜。
- 人员：任务分配/激活/完成、接令后目标进度、失联持续旧任务时间、阻挡、局部避险、中央改派与本地细化次数。
- UAV：指定任务兑现、有效目标服务、充电、耗尽、阻挡、动作接管、各机号弱项。
- 成本：Agent实际决策窗口数、失败窗口、token账单若可得、工具等待wall-clock、外部API次数、训练GPU小时与环境步数。

容量、吞吐、有效吞吐、任务成功不能混用。AoI单位同时报tick和秒。火格面积可换算m²，但注明原火灾动力学未真实标定，不称真实救灾效果。

## 14. 实施顺序与阶段出口

### P0：接管与基线保护

记录git状态、根目录、版本、依赖、Actor哈希、CPU/GPU；避免改用户已有工作。实测旧模式最小重放，列出修改文件。若权重或代码版本不同，记录差异并适配，不盲从本文行号。

### P1：单位、节点认知、消息传输与泄漏边界

先做无Actor的小图、固定节点通信测试。实现时间戳融合、消息队列、TDMA、计费和交付日志；封闭旧全局共享捷径。通过第13.1节相关测试。

### P2：人员任务与联合计划

支持人工JSON和Agent文件桥接口，但此阶段先用固定测试JSON/程序化启发式验证“发出≠生效”、不被自动重派覆盖、局部寻路和失联继续旧任务，不要求Agent逐窗口参与。完成一个不调用API的端到端小演示。

### P3：可观测语义与Actor视图

构造基站摘要与本地执行视图、radio_v3和奖励事件；先CPU跑A0与简单任务控制探针。提交字段来源表和负载/服务能力诊断。FIFO与语义调度都必须能跑。

### P4：定向续训与从头对照

机制已通过才使用GPU。按T0—T4训练，全程启发式高层＋启发式人员靠近，不接任何在线大脑；保存所有有效/无效批次、采样配置和日志，不覆盖原Actor。开发集选模后锁定测试，再进入真实Agent对比。

### P5：正式对照、前端和交付

执行Agent亲自完成必要规划窗口，跑配对实验并生成报告、轨迹、指标、复现指令和网页演示。若没有取得任务改进，依然交付准确结论和失败机制，不用挑seed/改口径制造成功。

可以穿插前端开发，但不能用前端“看起来有链路”代替后台机制测试。不能因为训练慢就省略真值隔离和数据交付。

## 16. 明确禁止的捷径

- 不把旧Actor覆写后仍沿用旧哈希/旧指标；不把新模型“可加载”当性能验收。
- 不把覆盖率字段直接改成Mbps或给旧355维权重塞371维输入。
- 不用真实地图寻路、真值火区规划、全局共享认知换取好成绩，再宣称通信受限。
- 不把bit容量数值、发送事件或收到一部分消息当完整交付。
- 不使用付费千问替代用户指定的Agent大脑；不静默启发式回退。
- 不用真实未来收益指导在线语义调度；离线反事实/评估可以看真值，但必须与正式规划隔离。
- 不为了提高速率奖励重复发包、增加无用流量、忽略控制截止期或把低电量机钉在高吞吐点。
- 不把原Actor的91%旧半径中继成绩当新信道服务成功率。
- 不将旧三局、固定命令重放、从同一轨迹补记的指标当新的独立试验。
- 不默认占满8卡；不把完成一个训练进程当完成本任务。
