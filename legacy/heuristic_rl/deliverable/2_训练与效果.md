# 训练配置、曲线与效果

## 1. 训练配置

| 项 | 取值 |
|---|---|
| 算法 | MAPPO（中心化 Critic + 参数共享 Actor），GAE(λ=0.95)、clip 0.2、5 个 epoch、Huber 值损失、running ValueNorm |
| 网络 | Actor：LayerNorm → 2×[Linear(384)+ReLU+LayerNorm] → Linear(9)，正交初始化（输出层 gain=0.01）<br>Critic：输入 `[自身(355), 队友均值(355), 全局(8)]`，同结构 |
| 成果版本超参 | `lr 5e-4 / entropy 0.01 / n_minibatch 2 / gamma 0.995 / hidden 384` |
| 采样 | 96 个并行环境（24 个进程 × 4 环境），rollout 64 步 |
| 规模 | **16M 环境步**（每变体），8 张 H20 各跑一个变体，约 5.5 小时 |
| 硬件 | 8×H20 96GB + 192 核；GPU 只跑网络，`act`+`update` 占单次 update 不到 5%，瓶颈在 CPU 采样 |

上层在训练期是一个**读态势的规则规划器**（不是随机发指令）：返航余量不足的先派去补给，
至少留 1–2 台中继（指定当前未被覆盖的人员），其余按探索率决定搜寻还是巡逻，
并给出显式目标。每 25 步重规划一次。

> 对照实验：专门训了一个用**随机指令**（30% 全队同任务 + 每机独立均匀采样）的变体。
> 它是 8 个变体里唯一**在退**的——回报涨到最高 936，但覆盖率 0.530→0.334、
> 人员已知火情 0.250→0.211。说明训练期的指令分布必须贴近部署时的分布。

## 5. 已知局限（如实记录）

1. **单回合方差大**。同配置三个种子的扑灭格数 252 / 162 / 229、火情发现率
   1.000 / 0.860 / 0.385。看单回合会误判，结论必须用多回合均值（`--episodes 5`）。
2. **过火面积是噪声级指标**。6 种子配对测试（同一世界 random vs greedy）逐回合差值
   均值只有 +0.0004，而扑灭格数分得很开（14 vs 396）。**压制能力请看 `扑灭格数`**，
   过火面积只作参考。
3. **指令敏感性偏弱**，见上文第 3 节。
4. **上层规划器是手写规则，其自身决策质量未被优化**。"探索率 0.70 转巡逻"
   "最多 2 台中继"等阈值都是人工设定；低层是在这套规则的分布上训出来的，
   若换成风格差异很大的 LLM 规划器可能需要适配（可把规划器参数也随机化来扩宽训练分布）。
5. **覆盖率在演示里只有 0.49**。人员合围完一处火要长途转场，1–2 台中继跟不上
   转场中的队伍；需要上层在转场期临时多派中继。

## 6. ReAd critic（已训练）

顺序不能颠倒，且**必须先冻结低层**：ReAd 的 `Q_θ` 是在固定低层执行器下回归出来的，
低层还在变的话 critic 的回归目标就是移动靶。

1. **（已完成）** 训练任务条件低层策略 → 冻结 `model/actor_best.pt`
2. **（已完成）** 冻结低层 + 多样化计划分布采集 `D = {(s_t, τ_t, r_t)}`：4096 回合 / **96769 段**
3. **（已完成）** 拟合 `Q_θ(s, τ)` → `model/read_critic.pt`
4. **（已完成）** 用 `S_ReAd(τ_i) = Q_θ^{1:i} − Q_θ^{1:i−1}` 与阈值 α 做下发门限（验证见下）

代码：`lowlevel/read_critic.py`，三个子命令 `collect / train / eval`。

### 6.1 状态与计划的编码

| 项 | 维度 | 内容 |
|---|---|---|
| 状态 `s` | 254 | 时间进度、探索率、火情发现率、人员已知火情、覆盖率、AoI、活跃/已合围火点数（9）+ **10×10 双通道粗视图**（200）+ 每机 位置/电量/返航余量/在位（5×8）+ 人员聚合（5） |
| 计划 `τ` | 93 | 每机 `UavOrder.to_vector()`（10）+ 存在位，共 8 槽 + 任务/模式计数（5） |

与原论文的两处偏离（代码头部已注明）：容器内无法下载 BERT 权重，且我们的指令本来就是
结构化 JSON，所以用**结构化编码**代替冻结 BERT；状态额外带粗视图，否则无法判断
"指向某片未知区域"这条建议好不好。

### 6.2 段奖励与两阶段拟合

高层一段 = 25 步（重规划周期）。段奖励只用可交付指标的差分（不是低层那套 shaping）：
`6·Δ探索 + 4·Δ火情发现 + 3·Δ人员已知 + Δ扑灭格数/100 + 0.5·Δ合围数 + 0.5·平均覆盖率 − 4·Δ过火 − 0.5·新增耗尽`。

直接把 `Q` 回归到 MC 回报**不 work**，这是本轮最关键的一个坑：

- 段回报 std 4.30，其中几乎全部方差来自"这局火场长什么样、还剩多少时间"，
  单次指令的效应只有 0.2 量级；
- 单塔网络按验证 RMSE 选点会停在**第 1 个 epoch**，此时四类计划的 `Q` 差 < 0.08，门限完全失效
  （实测排序准确率仅 61.5%）；按 segment 随机切验证集还会因同回合相邻段强相关而虚高到 R²=0.965。

改成 `Q(s,τ) = V(s) + A(s,τ)` 两分支 + 两阶段：

1. `V(s)` 只吃态势，用 MC 回报拟合（按回合切分的验证 RMSE 2.14，R² 0.756）；
2. 冻结 `V`，优势分支用 **TD 目标** `r + γ V(s′) − V(s)` 拟合（γ=0.95）。
   未来回报被替换成期望，目标 std 从 4.30 降到 **0.71**，指令效应才浮出来。

选点用 `RMSE + 3×计划效应标定误差`——计划类别是与态势独立采样的，
各类别的目标均值就是该类计划效应的无偏估计，`A` 的类别均值应当复现它。

### 6.3 结果（验证集 72770 条前缀样本 / 端到端 40 回合）

各类计划的优势，与目标同序（数值被输出收缩项压缩）：

| 计划类别 | `A` 预测 | TD 目标优势 |
|---|---|---|
| 规划器 planner | −0.034 | +0.015 |
| 单条扰动 perturb | −0.053 | −0.002 |
| 全随机 random | −0.112 | −0.136 |
| 退化（全队同任务） | −0.141 | −0.203 |

同一态势下配对打分（40 回合、960 对）：`Q(规划器) > Q(退化)` **80.4%**、`> Q(随机)` **76.6%**。

端到端门限实验（把"随机 LLM"的计划过一遍门限，α 取规划器增量优势的 20 分位 = −0.027，
最多重采样 8 次，40 回合均值）：

| | 全图探索率 | 火情发现率 | 人员已知火情 | 扑灭格数 | 合围火点数 | 耗尽机数 |
|---|---|---|---|---|---|---|
| 不过门限 | 0.687 | 0.635 | 0.635 | 209 | 2.35 | 3.30 |
| **过 ReAd 门限** | **0.734** | **0.831** | **0.831** | **235** | **2.73** | **2.35** |

只是筛掉明显糟糕的分工，火情发现率就从 0.635 拉到 0.831、耗尽机数从 3.30 降到 2.35。

### 6.4 反事实配对测试（最严格的一档）

前面三项测试都有各自的漏洞：回归误差不等于会挑计划；按"计划类别"比较只验证了**类别期望**的排序；
门限实验混入了低层策略自身的方差。最严格的做法是**同一状态分叉**：
`deepcopy` 环境 + `np.random.set_state()` 复位全局随机流（公共随机数），
只把指令换掉，各滚 25 步，量出两条分支的**真实**优势 `r + γV(s′) − V(s)`，
再看 critic 的 `Q` 之差符号是否与之一致。

`python3 lowlevel/read_critic.py probe --episodes 800 --workers 40`（约 25 分钟，19200 对）：

```
真实优势差 |dt| 均值 0.448   critic 预测差 |dq| 均值 0.126
符号一致率 57.9%            （随机猜 50%，二项 z = 21.8）
只看差距明显的一半          62.8%
corr(dq, dt) = 0.268
```

标定单调（按预测差分箱 → 真实差均值）：−0.236 / −0.059 / +0.009 / +0.038 / +0.243。

分类别对：

| 对比 | 一致率 |
|---|---|
| 退化 vs 规划器 | 62.6% |
| 退化 vs 扰动 | 60.4% |
| 规划器 vs 随机 | 59.4% |
| 退化 vs 随机 | 57.0% |
| 扰动 vs 随机 | 56.5% |
| 规划器 vs 单条扰动 | **51.2%**（基本分不出，两者本来就只差一条子任务） |

**怎么读这两个数**：6.3 的 80.4% 是"类别期望"意义上的排序（这一类计划平均更好），
这里的 57.9% 才是"单次决策"意义上的排序。两者不矛盾——单段里低层策略自身的随机性
就贡献了 |dt| 的大头，而 critic 只能预测其中可由指令解释的那一部分。
门限之所以仍然有效（6.3 的表），是因为它做的是多次重采样后的**统计筛选**，不是单次判决。

### 6.5 语义单元测试（找到了一个真实缺陷）

在真实态势上手工构造"明显该被否掉"的指令，看 `Q(规划器)` 是否更高（480 次比较）：

| 构造的坏指令 | 规划器胜出 | 平均 Q 差 |
|---|---|---|
| 全队中继（没人搜寻） | **98.1%** | +0.208 |
| 全队搜寻（没人中继） | **94.8%** | +0.190 |
| 巡逻环半径给 1（过小） | 61.7% | +0.045 |
| 全队补给（电量还够） | 54.0% | +0.038 |
| **搜寻目标指向已探索区** | **29.2%** | **−0.059** |

前两行说明 critic 把"任务配比"这件事学明白了。后三行是缺陷，其中最后一行是**方向性错误**：
把搜寻目标指到无人机脚下（等于什么都不探索），critic 反而给出更高的分。
成因是这类指令在训练分布里几乎不出现——采集时的显式目标要么来自规划器的未知区域中心、
要么是均匀随机坐标，"零距离目标"是分布外输入。要修得往采集分布里专门注入这类反例
（distractor orders），本轮未做。

### 6.6 复现命令

```bash
python3 lowlevel/read_critic.py collect --episodes 4096 --workers 40 \
        --data lowlevel/runs/read/dataset_big.pkl        # 约 40 分钟（192 核）
python3 lowlevel/read_critic.py train --data lowlevel/runs/read/dataset_big.pkl \
        --v-epochs 20 --epochs 40 --batch 1024 --device cuda
python3 lowlevel/read_critic.py eval  --episodes 40      # 类别排序 + α 标定 + 门限对照
python3 lowlevel/read_critic.py probe --episodes 800 --workers 40   # 反事实配对 + 语义单元测试
```

接入 LLM 时只改一处——`TaskConditionedEnv.set_plan()` / `LowLevelController.set_plan()`
的调用方，从规则规划器换成「LLM 生成 JSON → `ReAdCritic.score()` 打分 → `S_ReAd > α` 才下发」：

```python
from lowlevel.read_critic import ReAdCritic
critic = ReAdCritic(path="model/read_critic.pt")
inc, q = critic.score(env, orders)      # inc[i] 是第 i 条子任务的增量优势
if inc.min() > alpha:
    env.set_plan(orders)                # 否则让大模型重新规划
```

### 6.7 这一步的已知局限

1. **单次决策的判别力只有 57.9%**（见 6.4）。门限有效靠的是多次重采样的统计筛选，
   不能把它当成"一次就能判对"的裁判。
2. **细粒度建议判别弱、甚至有方向性错误**（见 6.5 的"目标指向已探索区"）。
   根因是采集分布里没有这类反例。
3. **α 是离线标定的**（规划器增量优势的 20 分位），没有按"重采样预算 vs 收益"扫过；
   门限对照里平均每回合触发约 100 次重采样。
4. **单段计划效应本身很小**（最大类别差 0.24，段回报 std 4.30）：低层策略对"分工不合理"
   有相当鲁棒性，这压低了 critic 的信噪比上限。
